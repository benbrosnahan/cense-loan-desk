# A11Y-05: Section change is not announced

**P3** · effort S · Accessibility

Switching sections swaps the content silently for screen-reader users: focus stays on the pressed button and nothing names the new section, so they have to explore to learn what changed.

| | |
|---|---|
| Who it hurts | A screen-reader borrower who presses a section button hears nothing about the new section and has to step past the remaining section buttons to find out whether anything changed. |
| Standard | No WCAG 2.2 failure. Filed under SC 4.1.3 Status Messages (AA), but W3C's Understanding page lists content shown when a user selects a different tab as not a status message and says the criterion does not require authors to create new messages. With one URL, the unchanged title does not fail SC 2.4.2. Announcing a view change is single-page-app best practice. |
| Where | Section bar below the summary (Your loans, Repayment plans, Payoff, Records) and the Next cards that call the same goTo. Every width; measured at 320, 375, 768, 1024, 1280 and 1440 on the local production build. |
| Code | [`src/app/page.tsx:72`](../../src/app/page.tsx#L72), [`src/app/page.tsx:205`](../../src/app/page.tsx#L205), [`src/app/page.tsx:521`](../../src/app/page.tsx#L521), [`src/app/page.tsx:522`](../../src/app/page.tsx#L522), [`src/app/page.tsx:546`](../../src/app/page.tsx#L546), [`src/app/page.tsx:862`](../../src/app/page.tsx#L862) |
| Test | `a11y.spec.mjs`: "A11Y-05 switching sections tells a screen-reader user which section is now shown" |
| Fix proof | Not attempted: fix proofs were run for P0 and P1 only. |

## Measured

Enter on each section button: focus stays on the pressed button, aria-current="page" moves to it (exactly one set), the URL does not change, document.title stays 'Loan Desk by Cense — every student loan you have, in one place', and Next.js's route announcer stays empty. Text added to an already-present live region within 1,100 ms: Plans none, Records none, Loans none, Payoff only its debounced <output> summary at about 710 ms (none when no plan is chosen). Plans inserts two polite hint regions (goal and employer) together with their text, and Payoff inserts its strategy blurb the same way; none names the section. No toast fires. In Chrome's accessibility events, a focused button gaining aria-current fired no state event, while aria-selected, aria-expanded and aria-pressed fixtures did. The new section's first heading is 0 to 3 Tab stops after the pressed button (Records 0, Payoff 1, Plans 2, Loans 3), and those stops are only the remaining section buttons. The Next cards are equally silent and also drop focus to BODY (A11Y-03). No screen reader was run.

## Required

When the section changes, a screen-reader user hears which section is now shown, through a polite status message or a focus move to the new section. This is best practice, not a WCAG 2.2 requirement.

## Reproduce

1. Open http://localhost:3100 and click 'Look around with example loans'.
2. Tab to the section bar and press Enter on 'Repayment plans'. The content below changes.
3. In DevTools, check that document.activeElement is still the 'Repayment plans' button, that document.title has not changed, and that no element with role="status" or aria-live received text naming the section.
4. Repeat with Records and Your loans: no live region changes at all. On Payoff only the payoff summary appears, about 0.7 s later.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "A11Y-05"`.

## Fix

Add one always-present polite status node and set it when the section changes. In src/app/page.tsx:
// beside the other useState calls (lines 122-134)
const [sectionNote, setSectionNote] = useState("");
// in goTo (line 205)
setSectionNote(`${TABS.find((t) => t.id === next)?.long} section`);
// beside <Toast> at line 862
<p className="sr-only" role="status">{sectionNote}</p>
The node is mounted from the start and empty, so the first change is spoken, and pressing the current section again sets the same text and repeats nothing. No new dependency.

## Severity

Every screen-reader borrower meets it on each section change, but it is not a WCAG failure (W3C excludes content swapped by picking a tab from status messages), aria-current is already set correctly, nothing is lost or miscalculated, and the new section's heading is 0 to 3 Tab stops past the pressed button, so adding the announcement is hardening.

## Verification

Split 1 to 1 (reproduce confirmed, standards refuted the WCAG citation), then confirmed by the tie-breaker; both skeptics built the fix and saw it work.

The standards skeptic refuted the WCAG claim: W3C's Understanding page for SC 4.1.3 counts content shown when a user picks a different tab as not a status message and says the criterion is not meant to make authors create new messages; one URL means the unchanged title is no SC 2.4.2 failure; and SC 4.1.2 does not apply, because the markup is a native button with standard aria-current and the missing event is browser behaviour. That skeptic rated P3 until a real screen reader shows silence on Records and Loans, and P2 if it does. The filer and the reproduce skeptic rated P2. Both skeptics say 'announces nothing' is broader than the evidence, which shows DOM and accessibility-event silence, not what a screen reader says. Corrections: Plans inserts two hint regions (goal and employer), not one, and Payoff also inserts its strategy blurb.

Fix choice: the filed status node, which both skeptics built in scratch copies (tsc and next build pass). It read 'Repayment plans section', 'Payoff section', 'Records section' and 'Your loans section' within 450 ms at 375 and 1280, and axe results did not change. Severity is P3 under this report's rubric: no WCAG failure, no wrong figure and no lost data. Cautions from the skeptics, none tested with a screen reader: goTo also runs for the Next cards and for 'Add my own' on the example banner (page.tsx:443), which sets 'Your loans section' while already on Loans, which is harmless. On Payoff this note is followed by the debounced summary; W3C warns about chattiness (status-messages.txt line 80).
