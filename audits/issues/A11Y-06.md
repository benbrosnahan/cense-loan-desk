# A11Y-06: Radio choices ignore arrow keys

**P2** · effort S · Accessibility

The radio-button choices (the two Plans questions, loan type, payoff order) ignore the arrow keys and make every option its own Tab stop, so keyboard borrowers Tab through 8 stops instead of 2 on Plans, and pressing an arrow scrolls the page instead of changing the answer.

## Measured

Each option is a <button role="radio"> with no tabindex, so Tab visits every one: 8 stops on Plans (2 groups of 4) where the pattern gives 2, 4 on Add a loan, 2 on Payoff. ArrowDown, ArrowRight, ArrowUp and ArrowLeft never move focus or aria-checked in any group. The keys are not inert: ArrowDown and ArrowUp scroll the page 40 px, Home jumps to the top and End to the bottom (scrollY 201 to 4301 on Plans at 375). Space and Enter select. The accessibility tree exposes role radio, the option name and its checked state. A native radio fixture in the same probe moved focus and selection on all four arrows and left the group with one Tab.

## Required

APG Radio Group pattern: the group is one Tab stop (the checked radio, or the first if none is checked); Down and Right move focus to the next radio and check it, Up and Left the previous one, wrapping at both ends.

## Reproduce

1. Open http://localhost:3100, click 'Look around with example loans', then open Repayment plans.
2. Tab to an option in 'What matters most to you?' and press the arrow keys. The selection does not move; Up and Down scroll the page instead.
3. Keep pressing Tab. Each of the 4 options is its own stop, 8 stops across the two questions before the income field.
4. The same holds for 'Loan type' in Add a loan and 'Payoff order' on Payoff.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "A11Y-06"`.

## Fix

One change in ChoiceGroup covers all four groups (src/components/shared/ui.tsx):
// line 8
import { useId, useRef, useState } from "react";
// inside ChoiceGroup, before the return
const refs = useRef<(HTMLButtonElement | null)[]>([]);
const current = Math.max(0, options.findIndex((o) => o.value === value));
const step: Record<string, number> = { ArrowDown: 1, ArrowRight: 1, ArrowUp: -1, ArrowLeft: -1 };
const onKeyDown = (e: React.KeyboardEvent, i: number) => {
  if (e.altKey || e.ctrlKey || e.metaKey) return; // leave browser shortcuts such as Back alone
  const d = step[e.key];
  if (!d) return;
  e.preventDefault();
  const n = (i + d + options.length) % options.length;
  onChange(options[n].value);
  refs.current[n]?.focus();
};
// line 374
{options.map((o, idx) => {
// on each <button>
ref={(el) => { refs.current[idx] = el; }}
tabIndex={idx === current ? 0 : -1}
onKeyDown={(e) => onKeyDown(e, idx)}
No new dependency.

## Severity

Every keyboard borrower, and screen-reader users on a desktop, meet it in the two Plans questions, the loan-type choice and the payoff order, but Tab plus Space or Enter still answers every group and no WCAG criterion fails, so it is a real but bounded defect.

## Verification

Confirmed by 2 of 2 skeptics (reproduce, standards); both kept P2 and both built the fix.

<details><summary>Dissent and notes</summary>

Standards skeptic: the filed SC 4.1.2 citation is wrong, since role, name and checked state are exposed and 4.1.2 sets no keyboard pattern, so this is an ARIA 'should' and APG pattern gap rather than a WCAG failure. Home and End are not in the APG radio pattern, so they are not part of the defect. The screen-reader half of the impact is inferred: no screen reader was run, browse-mode arrows move the reading cursor, and phone screen readers do not use arrows. Reproduce skeptic: the filed 'nothing happens' is not quite right, because Up and Down scroll the page and Home and End jump it. The filed fix swallowed Alt, Ctrl and Cmd plus an arrow (selection moved, defaultPrevented true), which would block the browser Back shortcut (inferred; headless Chromium cannot exercise the navigation); the corrected fix adds the modifier guard. Both noted the filed snippet also needs useRef in the ui.tsx:8 import and an idx parameter at ui.tsx:374.

Fix choice: the reproduce skeptic's corrected snippet, built and run at 375 and 1280: 2 Tab stops on Plans, arrows wrap and select, no page scroll, Shift+Tab lands on the checked option, Alt, Ctrl and Cmd plus an arrow are left alone, a typed rate survives an arrow walk through the loan types and an auto-filled rate is suggested again. The standards skeptic built the filed version separately and saw the goal hint and localStorage follow the arrows and the Payoff group work. Selection follows focus, as the pattern specifies, so arrowing through 'Loan type' changes the type as it goes. Shift plus an arrow still moves the selection in the corrected build. Related: A11Y-12 (forced colors hides the selected state) restyles the same buttons.
