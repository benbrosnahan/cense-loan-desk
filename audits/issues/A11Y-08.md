# A11Y-08: Slider track below 3:1

**P2** · effort S · Accessibility

The Payoff slider's unfilled track is 1.14:1 against its panel, so at the default $0 a low-vision borrower sees only a lone circle, with no sign that it slides or how far.

## Measured

The unfilled track #DCE7D8 on the slate-50 panel #F6F3E1 is 1.14:1, by computed colour and by pixel sampling: in Chromium at 320, 375, 1280 and 1440 with the value at $0 and at $100, and in real Mac WebKit at 375 and 1280 at $0. The track is 8 CSS px tall. The fill #26602D is 6.74:1 on the panel and 5.89:1 on the unfilled track, and the thumb ring is 6.74:1; those pass. At $0 (--fill 0%) no fill is drawn: a line across the slider reads thumb ring, white thumb, then only #DCE7D8 to the end. The only text in the panel at $0 is the label, the $ sign and the presets None, $25, $50, $100 and $200; the typed field is empty with placeholder 0, and the $500 maximum appears nowhere.

## Required

3:1 against adjacent colours for visual information needed to identify a control and how to operate it (WCAG 2.2 SC 1.4.11; Understanding 1.4.11, User Interface Components). The author styles the track (globals.css:93-106), so the browser-default exception does not apply.

## Reproduce

1. Open http://localhost:3100 in a fresh browser window and tap 'Look around with example loans'.
2. Open Plans and choose a plan, for example with the 'Use <plan name> as my plan' button on the top pick; Payoff shows the slider only once a plan is chosen.
3. Open Payoff. 'Extra each month' starts at $0 with 'None' pressed: the slider is a green ring at the left end and a pale track (#DCE7D8 on #F6F3E1, 1.14:1) that is hard to make out.
4. Tap $100: the filled part, up to 20%, is 6.74:1, and the rest of the track is still 1.14:1.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "A11Y-08"`.

## Fix

In src/app/globals.css, give each engine's track a 1px slate-500 inner outline by adding one line to each of the two existing track rules:

```diff
 .range::-webkit-slider-runnable-track {
   height: 8px;
   border-radius: 999px;
   background: linear-gradient(
     to right,
     #26602d 0 var(--fill, 0%),
     #dce7d8 var(--fill, 0%) 100%
   );
+  box-shadow: inset 0 0 0 1px #5c7f5f; /* slate-500: 4.04:1 on the slate-50 panel */
 }
 .range::-moz-range-track {
   height: 8px;
   border-radius: 999px;
   background: #dce7d8;
+  box-shadow: inset 0 0 0 1px #5c7f5f;
 }
```

Keep the two rules separate, as the file already does: one selector list naming both pseudo-elements would be dropped by any engine that does not know one of them. Built and measured: the track edge becomes #5C7F5F (92, 127, 95), 4.04:1 on the panel in Chromium and in real Mac WebKit and 3.54:1 against the unfilled track, and it shows at $0. The fill and thumb keep their contrast, and the $0 default does not change.

## Severity

Low-vision borrowers hit this on every visit to Payoff, because the slider starts at $0 and then shows only its thumb. The typed field and the five presets set and show the same amount, so no one is blocked and no figure is wrong; what is lost is the slider's range and where the value sits in it.

## Verification

Confirmed by 2 of 2 skeptics (reproduce, standards); both kept P2.

<details><summary>Dissent and notes</summary>

No skeptic refuted the finding or changed its severity. The standards skeptic called it an interpretation: W3C's guidance never names slider tracks, and its one slider example concerns the thumb, which passes and carries the value, so the filing's 'and its state' is loose. The failure rests on 1.4.11's identify-and-operate test: at $0 what a low-vision user can rely on is a lone ring that could be a radio button, and the typed field and presets repeat the value but not the range or the position in it. The reproduce skeptic noted the track is faintly visible at typical vision, so 'only the thumb can be seen' is the low-vision reading. The filing's 'WebKit rule injected' meant the -webkit- rule in Chromium; both skeptics then ran it in real Mac WebKit, where it draws the line as claimed (the reproduce skeptic's WebKit snapshot had shifted colours, so the 4.04 WebKit figure comes from the standards skeptic). The -moz rule has never run (no Firefox on this machine), and iOS Safari was not tested.

One member, nothing to merge. The skeptics built the fix as two one-line rules appended to the file; this issue places the same declaration inside the two existing rules instead. Same selectors, same declaration, so the rendered result is the same and the file keeps its shape. #5c7f5f is the palette's slate-500, the colour A11Y-07 proposes for input borders, so the two fixes match. The outline also edges the filled part (#5C7F5F around #26602D); that is cosmetic and leaves the fill at 6.74:1. Before shipping, look at the slider once in Firefox and on an iPhone. If DX-04 moves globals.css to theme(), write the colour as theme("colors.forest.500"). Outside this issue, the reproduce skeptic noted the slider is only 58px wide at 320 with a 28px thumb; that was not filed or verified as a defect here. No runtime dependency is added and nothing leaves the device.
