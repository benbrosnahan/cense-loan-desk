# A11Y-12: Forced colors hides the selected state

**P2** · effort S · Accessibility

With Windows Contrast Themes on, selected choices, presets, school-year chips and the open section look the same as unselected ones, so borrowers who need high contrast cannot see what they picked or where they are.

| | |
|---|---|
| Who it hurts | Borrowers using Windows Contrast Themes cannot see which goal, payoff order, extra-payment amount or school year they picked, or which section is open, and the extra-payment slider shows no track; on dark themes the payoff chart's line (2.79:1) and axis labels (3.63:1) are hard to see. |
| Standard | No WCAG 2.2 success criterion strictly fails, because colours changed by the user agent are outside the author's contrast responsibility. SC 1.4.11 Non-text Contrast (AA) is the yardstick for state, together with CSS Color Adjustment Module Level 1 (forced-color-adjust). |

The Payoff slider loses its track on both palettes. The payoff chart's line and axis text are too dark on the dark palette only. |

## Measured

Shipped app, dark palette: selected and unselected radios have identical computed styles (background rgb(0,0,0), white text, 1px white border); presets and school-year chips are identical too, and the pixels are #000000 and #FFFFFF, differing only by the text itself. Section bar: the open tab's background computes to rgb(0,0,0) against transparent for the others, on a black pill with no border, so the pixels are identical. Light palette: the same loss, inverted (white background, black text, 1px black border). Slider: the track's background computes to none, and 19 of 1422 pixels in the slider's middle row are non-background, all of them the thumb. Chart: SVG keeps its authored colours (preserve-parent-color), so the data line is #26602D on black, 2.79:1, the axis text is #4A6E4D on black, 3.63:1 from pixels, and '$15k' over the area fill is 3.34:1; on the light palette the line is #26602D on white, 7.52:1. The summary split bar and plan bars paint their fill the same as their track, but the numbers stay ('Borrowed $27,000 Interest added so far $1,101'). The focus outline stays visible (2px solid). The state is still exposed as aria-checked, aria-pressed and aria-current.

## Required

The selected state, the slider's extent and the chart lines stay visible when the system palette is forced. As a yardstick, SC 1.4.11 asks 3:1 for the visual information needed to identify a component's state.

## Reproduce

1. Turn on forced colors: on Windows 11, Settings > Accessibility > Contrast themes, pick Night sky (dark) or Desert (light) and apply; or in Chrome DevTools open Rendering and set 'Emulate CSS media feature forced-colors' to 'forced-colors: active'.
2. Open http://localhost:3100 and click 'Look around with example loans'. The open tab in the section bar looks the same as the other three.
3. Open 'Repayment plans' ('Plans' on a phone) and click 'Pay the least overall' under 'What matters most to you?'. It looks the same as the other three choices.
4. On any plan card that shows a monthly payment, press 'Use ... as my plan', then open Payoff. Click the $100 preset and 'Smallest balance first': neither looks different from its neighbours, the slider shows only its round thumb with no track, and on a dark theme the chart line is dark green on black.
5. Click 'Add my own' on the example-loans banner and pick a school year: the chosen chip looks the same as the rest.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "A11Y-12"`.

## Fix

Add one forced-colors block to src/app/globals.css after the slider rules (after line 138, before the reduced-motion block at line 140). It gives every selected control the system Highlight colours, and gives the slider track and the chart system colours.
```css
@media (forced-colors: active) {
  [role="radio"][aria-checked="true"],
  button[aria-pressed="true"],
  [aria-current="page"] {
    forced-color-adjust: none;
    background: Highlight !important;
    color: HighlightText !important;
  }
  [role="radio"][aria-checked="true"] *,
  button[aria-pressed="true"] *,
  [aria-current="page"] * {
    color: inherit !important;
  }
  .range::-webkit-slider-runnable-track {
    background: ButtonText !important;
  }
  /* Firefox. Keep it a separate rule: grouped with the WebKit selector, both would be dropped. */
  .range::-moz-range-track {
    background: ButtonText !important;
  }
  figure svg path[stroke]:not([stroke="none"]),
  figure svg line[stroke] {
    stroke: CanvasText !important;
  }
  figure svg text {
    fill: CanvasText !important;
  }
}
```
The first two rules are both needed: without forced-color-adjust: none, Chromium paints a black backplate behind the label text, and without the * rule the 'Often called avalanche' sub-label keeps text-white/85 (ui.tsx:396) and reads 2.1:1 on the Highlight fill. Measured with the block injected and in a throwaway build: selected controls #00B8CC with black text, 8.73:1, on the dark palette and #37336D with white text, 11.31:1, on the light; the slider track drawn across 1357 of 1422 mid-row pixels; chart lines and labels in CanvasText with the dash kept. The same selectors also cover the selected-plan button and the hide-amounts toggle.

## Severity

Affects borrowers who use Windows Contrast Themes (forced colors), an uncommon environment, on every visit: the visual cue for the chosen goal, payoff order, extra-payment preset, school year and open section is gone. No figure is wrong, the state still reaches screen readers through aria-checked, aria-pressed and aria-current, nearby text (the goal hint, the order blurb, the typed extra amount, the date field, the section heading) lets them infer it, and no WCAG criterion strictly fails, so it is a bounded defect.

## Verification

Confirmed by 2 of 2 skeptics (standards, reproduce); both kept P2.

Neither skeptic disputed the finding or P2. Corrections, used above: the selection loss happens on the light forced palette too, not only the dark one, while the chart problem is dark-palette only (#26602D on white is 7.52:1). The axis-text ratio, filed as derived from authored colours, is now pixel-measured at 3.63:1. The standards skeptic added the Firefox track rule (globals.css:102 styles a separate Firefox track) and offered a GrayText stroke for gridlines as optional. The reproduce skeptic found no regression needing a change, and noted that a computed-style check on the section bar passes falsely, because the computed backgrounds differ while the pixels are identical.

One member, so there were no competing fixes. Not adopted: the optional GrayText stroke for figure svg line[stroke], because that selector also matches the legend keys at PayoffRunway.tsx:146 and :164, which would then stop matching the CanvasText data lines. Measured side effects of the fix: on the light palette, gridlines and tick marks turn black like the data lines and differ only by width; on a focused selected control the outline turns transparent because the control is no longer forced, but the 2px box-shadow ring stays visible (focus changes 11966 pixels on the dark palette, 6379 on the light). The summary split bar and plan bars stay invisible under forced colors, which is acceptable because their numbers sit beside them. Limits: Chromium emulation only, not real Windows Contrast Themes; Firefox was not run, so the -moz rule is untested. The authored chart colours are at PayoffRunway.tsx:29-32.
