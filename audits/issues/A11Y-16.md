# A11Y-16: aria-controls points at a missing id

**P3** · effort S · Accessibility

Collapsed loan rows, plan cards and disclosures point aria-controls at panels that are not rendered, so a screen reader's jump-to-controlled-element command has nothing to land on.

| | |
|---|---|
| Who it hurts | Screen-reader users whose software offers a jump to the controlled element get nowhere from a collapsed loan row, plan card or disclosure; aria-expanded still announces collapsed or expanded correctly, so no content or figure is lost. |
| Standard | WAI-ARIA aria-controls (an ID reference to the element the control controls) and the WAI-ARIA APG Disclosure pattern. Not a WCAG failure: axe aria-valid-attr-value passes in all 7 states. |
| Where | Any viewport (measured at 1280x900). Every collapsed disclosure: the 8 loan rows and 'Clear my data' on Loans, 'Add more detail' in the loan form, the four 'How this plan works' buttons and 'Two rules worth knowing about multiple loans' on Plans, 'See these numbers as a table' and 'See how a different plan changes this' on Payoff. With one loan row open, the other 7 rows still point at nothing. |
| Code | [`src/components/shared/ui.tsx:437`](../../src/components/shared/ui.tsx#L437), [`src/components/loans/LoanList.tsx:44`](../../src/components/loans/LoanList.tsx#L44), [`src/components/plans/PlansPanel.tsx:214`](../../src/components/plans/PlansPanel.tsx#L214) |
| Test | `a11y-details.spec.mjs`: "A11Y-16 every aria-controls on a loan row, plan card or disclosure points at an element on the page, open or closed" |

## Measured

aria-controls values that resolve to no element, with every disclosure closed: first-run form after a failed save 1 of 1, Loans 9 of 9, Loans with the add form 10 of 10, Plans 5 of 5, Payoff 2 of 2, first run and Records 0 of 0. With every disclosure open: Loans 7 of 9 and Loans with the add form 7 of 10 (the other loan rows, since only one row opens at a time), 0 elsewhere. Each site renders its panel only while open ({open && <div id=...>} at LoanList.tsx:74-75, PlansPanel.tsx:227-228 and ui.tsx:449-450) but sets aria-controls unconditionally. aria-describedby, aria-labelledby and label[for]: 0 dangling in every state, open or closed. axe aria-valid-attr-value: no violations in all 7 states with disclosures closed. With the filed fix on a production build: 0 dangling in every state, open and closed.

## Required

An aria-controls reference resolves to an element in the document while it is set: 0 dangling references in every state, open or closed.

## Reproduce

1. Open http://localhost:3100 and click 'Look around with example loans'.
2. In the DevTools console run [...document.querySelectorAll('[aria-controls]')].filter(e => !document.getElementById(e.getAttribute('aria-controls'))).map(e => e.textContent.trim().slice(0, 40)) and it lists the 8 loan rows and 'Clear my data'.
3. Open one loan row and run it again: the other 7 rows remain.
4. Open Plans and run it: the four 'How this plan works' buttons and 'Two rules worth knowing about multiple loans'.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "A11Y-16"`.

## Fix

Set aria-controls only while the panel is rendered. One attribute at each of the three sites, no new dependency:

// src/components/shared/ui.tsx:437 (the Disclosure component)
aria-controls={open ? id : undefined}

// src/components/loans/LoanList.tsx:44
aria-controls={open ? panelId : undefined}

// src/components/plans/PlansPanel.tsx:214
aria-controls={open ? panelId : undefined}

aria-expanded stays on every button, so the state is still announced, and React leaves the attribute out when the value is undefined.

## Severity

Screen-reader users meet it on every collapsed row or disclosure (9 at once on the Loans section), but nothing is lost: the collapsed state is still announced, a closed panel has nothing to jump to anyway, axe passes the attribute and every open panel's reference resolves. That makes it hardening, not a defect a borrower would notice.

## Verification

Confirmed by 1 of 1 skeptics (single P3 verifier, reproduce lens), who re-counted every state closed and open, ran axe, and built the filed fix: 0 dangling everywhere.

<details><summary>Dissent and notes</summary>

None. The lead and the verifier agree on every count and on P3. The verifier added the Loans-with-add-form state (10 of 10 closed, 7 of 10 open), and this report adds a probe that names each dangling button.

Fix choice: the filed conditional attribute, verified on a production build. Keeping every panel in the DOM behind the hidden attribute would also make the references resolve, but it renders all eight loan detail panels and every plan's detail up front: a bigger change for the same result. After the fix a collapsed row carries no aria-controls, so any test that finds loan rows with button[aria-controls^="loan-"] needs another selector; verify.mjs and the .verify folder do not use aria-controls, so nothing in the repo breaks.

</details>
