# A11Y-17: Heading outline and H1

**P3** · effort S · Accessibility

Headings make a poor outline: the H1 is the small 'Loan Desk' label, the loan form's H3 follows the H1 directly on Loans, the recommended plan's H2 says only 'Standard', and saved records have no headings, so screen-reader borrowers moving by heading lose context.

| Who it hurts | Screen-reader users moving by heading hear 'Standard' with no sign that it is the recommendation, meet a skipped level whenever the loan form is open, cannot jump between saved records, and get the app's name rather than its subject as the top heading; search engines that render the page get the same weak H1. |
| Standard | Best practice, not a WCAG failure: axe rule heading-order (moderate, tagged best-practice), with WCAG 2.2 SC 1.3.1 Info and Relationships and SC 2.4.6 Headings and Labels as the guidance behind it. No standard requires particular H1 text. |
| Where | Loans section with the add or edit form open, at every width measured (320, 375, 768, 1024, 1440); Plans, the top-pick card; Records, each snapshot card; the header H1 and the first-run headline in every state (local and live). |

## Measured

axe heading-order flags #loanform-title (moderate, tagged best-practice) in 10 of 10 runs: Loans with the add form and with the edit form at 320, 375, 768, 1024 and 1440 wide; the other 6 scenarios pass at every width. DOM order with the form open on Loans: h1 'Loan Desk', h3 'Add a loan' (or 'Edit this loan'), h2 'Your 8 loans'. Plans: the top pick's h2 reads only 'Standard', after a <p> reading 'Where we would start', and the plan cards below add an h3 'Standard'. Records: one h2, 'Your own record, dated'; snapshot dates such as 'Oct 1, 2026 at 8:00 AM' are <p>. First run, local and live at 412px: h1 'Loan Desk' at 18px in a 90x28 box (the same at 320 and 390; 20px and 100x28 from 768), while the visible headline is the h2 'Every loan you have, on one screen.' at 36.8px, with no 'federal' or 'student'. The page title is 'Loan Desk by Cense — every student loan you have, in one place'. Raw HTML has 0 headings. Fixes measured on production builds: heading-order clean in all 40 scenario-and-width runs, the Plans h2 reads 'Where we would start: Standard', one h3 per snapshot; with the H1 swap, exactly one H1 in all 8 states tested, verify.mjs 180 pass and 0 fail, no horizontal overflow.

## Required

Heading levels descend without skipping (axe heading-order passes in every state), each heading identifies its content when read alone, and each state has exactly one H1, which states the subject on first run.

## Reproduce

1. Open http://localhost:3100 with no saved loans. In the DevTools console run [...document.querySelectorAll('h1,h2,h3')].map(h => h.tagName + ' ' + h.textContent.trim()) and it returns H1 'Loan Desk' and H2 'Every loan you have, on one screen.'
2. Click 'Look around with example loans', then 'Add a loan', and run it again: H1 'Loan Desk', H3 'Add a loan', H2 'Your 8 loans'.
3. Open Plans: the H2 under 'Where we would start' is only the plan's name, and the plan cards repeat it as an H3.
4. Open Records and click 'Save today's snapshot': the card's date is bold text, not a heading.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "A11Y-17"`.

## Fix

Five small edits in four files, no dependency. The two members' fixes do not conflict and share the LoanForm change.

1. src/app/page.tsx:330-332: the brand label is the H1 only once loans exist (declare BrandTag after const empty at line 305):
const BrandTag = empty ? "p" : "h1";
<BrandTag className="font-display text-lg font-bold text-slate-900 sm:text-xl">
  Loan Desk
</BrandTag>

2. src/app/page.tsx:358-360: the first-run headline becomes the H1, same classes:
<h1 className="text-balance font-display text-[2.3rem] font-bold leading-[1.04] tracking-tight text-slate-900 sm:text-6xl">
  Every federal student loan you have, on one screen.
</h1>

3. src/components/loans/LoanForm.tsx:231 and 238: <h3> to <h2>, keeping id="loanform-title", tabIndex={-1} and data-autofocus.

4. src/components/plans/PlansPanel.tsx:345: hide the eyebrow from screen readers, and name the recommendation inside the heading at 349-351:
<p aria-hidden className="text-xs font-semibold uppercase tracking-[0.08em] text-white/80">
  Where we would start
</p>
...
<h2 className="font-display text-4xl font-bold leading-none sm:text-5xl">
  <span className="sr-only">Where we would start: </span>
  {PLAN_META[top.estimate.id].name}
</h2>

5. src/components/history/HistoryPanel.tsx:109-111: the snapshot date becomes a heading under the H2 'Your own record, dated':
<h3 className="tnum text-base font-bold text-slate-900">
  {niceDateTime(snap.takenAt)}
</h3>

## Severity

Screen-reader users who move by heading meet this on every visit (the skipped level only while the loan form is open on Loans), as do search engines that render the page. Nothing is hidden or wrong, axe flags only a best-practice rule, and the page title already names the subject, so it is polish.

## Verification

Confirmed by 2 of 2 skeptics, one single P3 verifier per member (reproduce lens); each re-measured the outline or the H1 and built its member's fix on a production build.
