# A11Y-18: Chart tooltip ignores Escape

**P3** · effort S · Accessibility

The payoff chart's hover box cannot be dismissed with Escape and covers about two thirds of the $30k and $15k axis labels, so a mouse or screen-magnifier user has to move the pointer away to read them.

| | |
|---|---|
| Who it hurts | Mouse users, and screen-magnifier users most since their pointer often rests on the chart, have the $30k and $15k labels and part of both lines covered until they move the pointer away; screen-reader users who open the table view hear a table with no name. |
| Standard | WCAG 2.2 SC 1.4.13 Content on Hover or Focus (AA), Dismissible clause. The table's empty name is best practice, not a WCAG failure. |
| Where | Payoff section with a plan chosen: the balance chart, on mouse hover, and the table under 'See these numbers as a table'. Measured at 375, 768, 1280 and 1440 wide; the plot is 662px wide from 768 up and 301px at 375. |

## Measured

With a real pointer at 375, 768, 1280 and 1440: the hover box is 176 x 99.2px, aria-hidden, pointer-events none, and unchanged after Escape at every width. It covers 69% of the $30k label and 64% of the $15k label with the pointer in the left 10% of the 662px plot, 51% and 47% at 15%, and none from 20%; in the 301px plot at 375 it covers 69% and 64% up to 30%, 3% at 40% and none from 50%. With the pointer at the left it also covers 38% of the solid line and 27% of the dashed line; mid-plot, 12% of the dashed line. The far right was not measured. The Hoverable clause passes: moving the pointer onto the box keeps it up and updates it. The chart svg has no tabindex, so it never takes keyboard focus. The table view has no caption and an empty accessible name (13 rows). With the fix on a production build the box is gone after Escape at every width; the filed caption read 'with the extra payment and with the required payment only' even at extra $0, when the only columns are 'When' and 'You owe'; the corrected caption reads 'Balance over time' at $0 and the long form at $100.

## Required

Hover content that covers other content can be dismissed without moving the pointer or focus, normally with Escape (WCAG 2.2 SC 1.4.13 Dismissible). The table view carries a name that matches its columns.

## Reproduce

1. In a desktop browser with a mouse, open http://localhost:3100 and click 'Look around with example loans'.
2. Open Plans and, if no plan is chosen yet, click the top pick's 'Use … as my plan' button.
3. Open Payoff and choose the $100 preset under 'Extra each month'.
4. Rest the pointer over the left tenth of the chart: a box with the month and both balances appears at the top left and covers most of the '$30k' and '$15k' labels.
5. Press Escape: the box stays.
6. Click 'See these numbers as a table' and inspect the table in the DevTools Accessibility pane: its name is empty. The audit fixture (8 loans, Standard chosen, $100 extra) gives the same chart.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "A11Y-18"`.

## Fix

Close the box on Escape from anywhere on the page, and name the table to match its columns. In src/components/charts/PayoffRunway.tsx (useEffect is already imported at line 16):

// after line 77
useEffect(() => {
  const onKey = (e: KeyboardEvent) => {
    if (e.key === "Escape") setHover(null);
  };
  window.addEventListener("keydown", onKey);
  return () => window.removeEventListener("keydown", onKey);
}, []);

// line 318, as the first child inside <table>
<table className="w-full text-left text-sm">
  <caption className="sr-only">
    {showBase
      ? "Balance over time, with the extra payment and with the required payment only"
      : "Balance over time"}
  </caption>
  <thead ...>

The listener sits on window because the svg cannot take focus, so keyboard focus is usually elsewhere, such as on the slider, while the pointer rests on the chart. By the code, the box returns on the next pointer move.

## Severity

It fails WCAG 1.4.13 (AA), but only in an optional hover layer: the debt-free dates are in the headline and legend and every figure is in the table, so no step of the payoff flow depends on it, which keeps it out of P1. It reaches mouse users, magnifier users most, only while the pointer rests in the left 15% of the plot (up to the left 30% in a 375px-wide window), and moving the pointer a little uncovers the labels, so it is polish rather than lost information.

## Verification

Confirmed by 1 of 1 skeptics (single P3 verifier, reproduce lens), who hovered with a real pointer at 4 widths, also tested the Hoverable clause, and built both the filed and the corrected fix.

<details><summary>Dissent and notes</summary>

None on severity: the lead and the verifier both rate it P3. Corrections adopted: (1) the filed caption named two series even when the table has one data column ('When' and 'You owe' at extra $0), so the caption now depends on showBase and goes first inside <table>. (2) 'Covers the axis labels' is scoped to about two thirds of each label and only with the pointer near the left of the plot; the verifier added the line coverage. (3) The lead left the Hoverable clause untested; the verifier found it passes.

Fix choice: the verifier's corrected fix, which keeps the filed Escape listener and fixes the caption text. The caption keys off showBase, not extra, because the 'Required only' column renders only when showBase is true (a required-only series that finishes in a different month), so the name always matches the columns. The figure already has an sr-only figcaption (PayoffRunway.tsx:308-310) and the svg an aria-label naming both finish dates, so the chart itself is named; only the table was not. The codebase has no other keydown or Escape handler, so the window listener clashes with nothing. The 375px measurements used a mouse, as in a narrow desktop window or a zoomed-in browser.
