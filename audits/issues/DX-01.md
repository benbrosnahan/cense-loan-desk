# DX-01: No CI, no npm test, no browser regression suite

**P2** · effort M · Testing and maintainability

No build step, CI job or committed browser test runs the money checks before a deploy, so a change that shows borrowers a wrong monthly payment still builds green and ships.

| | |
|---|---|
| Who it hurts | Every borrower relies on the author remembering one manual command before each deploy. When it is skipped, a wrong monthly payment ($139 instead of $311 on the example loans in the trial) or a loan list that is lost on reload reaches borrowers with no warning. |
| Standard | None. The AGENTS.md convention one filing cites is optional and creates no obligation. |
| Where | Repository root and the deploy path. package.json:5-10 has only dev, build, start and lint; there is no .github workflow, vercel.json, git hook or committed browser test, and README.md:89-91 documents `node verify.mjs` as a command to remember. Vercel runs `npm run build` unless the project's Build Command is overridden, which could not be checked from outside. GitHub shows no Vercel status, deployment or environment on any commit, so production (https://cense-loan-desk.vercel.app) is probably deployed with the Vercel CLI. |
| Code | [`package.json:5`](../../package.json#L5), [`package.json:7`](../../package.json#L7), [`verify.mjs:7`](../../verify.mjs#L7), [`verify.mjs:632`](../../verify.mjs#L632), [`README.md:90`](../../README.md#L90), [`README.md:142`](../../README.md#L142), [`src/app/page.tsx:152`](../../src/app/page.tsx#L152) |
| Test | `repo.spec.mjs`: "DX-01 a change that fails the money checks cannot get through the build that deploys" |

## Measured

No gate: `npm test` exits 1 with 'npm error Missing script: "test"'. There is no .github directory now or in history (`git log --all -- .github`: 0 lines). GitHub API: 0 workflows, and 0 statuses and 0 check runs on all 6 commits; main is unprotected. No vercel.json and no active git hooks. knip lists verify.mjs as the only unused file. None of the 31 tracked files is a test; the 143-assertion browser sweep at README.md:142 was never committed and predates the 2026-09-27 redesign.
A money bug ships green: with the denominator at src/lib/calc.ts:71 changed from `(pow - 1)` to `pow`, `npm run lint` and `npm run build` both exit 0 and verify.mjs never runs. On the example loans the served Plans tab then shows Standard at $139 a month instead of $311 (closed form $310.83) and $16,632 in total instead of $37,300. `node verify.mjs` on the same tree prints PASS 166 FAIL 14. Vercel's own builder run locally (`vercel build`, CLI 50.5.0) also completes, exit 0.
A saving bug ships green: with `loanStore.save(loans)` removed at src/app/page.tsx:152, tsc, lint, verify.mjs (PASS 180) and next build all pass, while a journey test fails at 'loan survives a reload'.
The hook works: with `prebuild: npm test`, the same money bug makes `npm run build` exit 1 with PASS 166 FAIL 14 before next build starts, and no .next folder is written. `vercel build` exits 1 with 'Error: Command "npm run build" exited with 1'. A clean tree exits 0 with PASS 180 and the same static files as an unhooked build. This holds on Node 24.13.0 and 25.9.0 and with CI=1 VERCEL=1 NODE_ENV=production. A Build Command override of `next build` skips the hook (exit 0 with the bug).
The hook stops only what verify.mjs asserts: in one skeptic's run 2 of 7 planted money bugs were stopped and 5 built green with PASS 180, for example IBR forgiveness after 25 years instead of 20 (total paid $42,120 becomes $52,650). In another run a money() display bug that shows 90% of every figure ($280 instead of $311) also built green.
Harm so far: none measured. All 6 commits pass their own harness (PASS 173 on four, 180 on two), and the live page chunk matches a HEAD build except for one webpack module id.
A committed browser test is cheap: a 50-line Playwright spec and 12-line config passed in 3.0 s against a production build and failed on the no-save change at the reload step. The existing 16-check walk passes 16/16 in 7.7 to 7.9 s on :3100.

## Required

A failing verify.mjs assertion stops the build that deploys, with no command to remember. `npm test` runs the harness. One committed browser test holds the key journey in place: add a loan, reload, choose a plan, read the debt-free date, export a spreadsheet with a valid ZIP signature, and make no request off the site's own origin.

## Reproduce

1. In the checkout run `npm test`: 'npm error Missing script: "test"'. `ls -a` shows no .github or vercel.json.
2. In a scratch clone (`git clone`, then `npm ci`), change src/lib/calc.ts:71 from `return (balance * r * pow) / (pow - 1);` to `return (balance * r * pow) / pow;`. Run `npm run lint` (exit 0) and `npm run build` (exit 0); verify.mjs never runs. `node verify.mjs` on the same tree prints PASS 166 FAIL 14.
3. Run `npm start`, open the page, click 'Look around with example loans' and open Plans: the summary reads '$139 a month on Standard' (correct: $311), and Standard's total reads $16,632 (correct: $37,300).
4. Apply the fix with `npm pkg set scripts.test="node verify.mjs" scripts.prebuild="npm test"` and run `npm run build` again: exit 1 with PASS 166 FAIL 14, and no .next folder.
5. Saving: in a fresh copy, delete `loanStore.save(loans)` at src/app/page.tsx:152. tsc, `npm run lint`, `node verify.mjs` and `npm run build` all pass. Start it, click 'Add my first loan', pick a school year, type a balance, click 'Save loan' and reload: the loan is gone.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "DX-01"`.

## Fix

1. Add the gate, the only step that can stop a deploy: `npm pkg set scripts.test="node verify.mjs" scripts.prebuild="npm test"`, which gives
```json
"scripts": {
  "dev": "next dev",
  "build": "next build",
  "start": "next start",
  "lint": "next lint",
  "test": "node verify.mjs",
  "prebuild": "npm test"
}
```
npm runs prebuild before build, so one failing assertion ends `npm run build` before next build starts. It adds no runtime dependency and no shipped byte.
2. Prove Vercel uses it. On a linked checkout run `vercel pull --yes && vercel build`. The log must say `Running "npm run build"`. If it says `Running "next build"`, clear the Build Command override in Project Settings, because an override skips prebuild.
3. Before each deploy, run it against a production build: `npm run build && npm start -- -p 3900`, then `npm run test:e2e`. The core of the spec:
```ts
await page.locator("#balance").fill("$12,340.50");
await page.getByRole("button", { name: "Save loan", exact: true }).click();
await page.reload();
await expect(summary).toContainText("$12,341");
// ...choose Standard, read "Debt free in <Month> <Year>", add $150 extra, export...
expect(readFileSync(await download.path()).subarray(0, 4).toString("hex")).toBe("504b0304");
expect(offOrigin).toEqual([]);
```
4. Optional signal: .github/workflows/ci.yml on push and pull_request with actions/checkout, actions/setup-node (`node-version` set to the Vercel project's major version, `cache: npm`), `npm ci` and `npm run build`, which now runs verify.mjs and lints. It cannot stop a CLI deploy, and it blocks nothing unless main gets branch protection with this job as a required check.
5. Optional: a short AGENTS.md written against the tree as merged, listing `npm test`, `npm run build` and `npm run test:e2e`, the rules (no network calls or analytics, empty first run, extra payment starts at $0, do not 'tidy' a cited value in src/data/plans.ts) and all four storage keys, including cense.loandesk.hideAmounts.v1. Add no CLAUDE.md, or one whose only line is `@AGENTS.md`.

## Severity

Every borrower is exposed, but only when a future regression in the money code or in saving is deployed without the author remembering `node verify.mjs`. Nothing is wrong today (all 6 commits pass their own harness and production matches HEAD), so this is a meaningful missed safeguard rather than a wrong figure on screen.
