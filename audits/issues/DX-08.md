## Required

A supported ESLint that runs through `npm run lint` before and after the Next upgrade, with a rule that flags a promise-returning onClick, and the jsx-a11y strict set holding today's clean result.

## Reproduce

In the app, the symptom this lint gap let through (filed as RES-08): 1. Open http://localhost:3100 and click 'Look around with example loans'. 2. Before clicking any download, turn the browser offline (DevTools, Network, Offline). 3. In 'Keep a copy' on Loans, click 'Download as a spreadsheet': no file and no message. 4. Open Records, click 'Save today's snapshot', then 'Download as a spreadsheet': the same. On a scratch branch, the lint gap itself: 5. `npm run lint` prints 'No ESLint warnings or errors'. 6. Replace .eslintrc.json with the config in the fix and run `npm run lint`: exit 1 with no-misused-promises at src/app/page.tsx:631:33 and src/components/history/HistoryPanel.tsx:72:23.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "DX-08"`.

## Fix

Now, on Next 14, in one commit so the build never breaks. .eslintrc.json:
```json
{
  "extends": ["next/core-web-vitals", "plugin:jsx-a11y/strict"],
  "plugins": ["@typescript-eslint"],
  "parserOptions": { "project": "./tsconfig.json" },
  "rules": { "@typescript-eslint/no-misused-promises": "error" }
}
```
Both plugins already come with eslint-config-next 14.2.35, so nothing new installs. In the same commit:
```tsx
// src/app/page.tsx:631
onClick={() => void doExport()}
// src/components/history/HistoryPanel.tsx:72
onClick={() => void download()}
```
and land RES-08's catch in doExport (page.tsx:279) and download (HistoryPanel.tsx:42): `void` alone turns lint green and leaves both downloads failing silently.

At the Next upgrade (SEC-02): install eslint@10, set "lint": "eslint ." at package.json:9, delete .eslintrc.json and add eslint.config.mjs, with the array named so the file does not warn about itself:
```js
import nextVitals from "eslint-config-next/core-web-vitals";

const config = [...nextVitals, { ignores: [".next/**", "out/**", "next-env.d.ts"] }];
export default config;
```
Then, directly above page.tsx:140:
```ts
// eslint-disable-next-line react-hooks/set-state-in-effect -- reads localStorage once after mount; this is the hydration gate
```

## Severity

Only the author is affected: no borrower sees a different figure or flow because of how lint is configured. The borrower-facing harm, a download that fails without a word, is RES-08 and is fixed by its catch, not by a lint rule, so this is hardening.
