# DX-09: noUncheckedIndexedAccess off

**P3** · effort S · Testing and maintainability

TypeScript's noUncheckedIndexedAccess is off, so a table or array lookup that misses, such as a gap in the poverty-line table behind the IBR payment, would turn a borrower's figure into NaN with no compiler error; all ten such reads are in bounds today.

## Measured

tsconfig.json sets strict: true (line 7) and not noUncheckedIndexedAccess. Baseline tsc: 0 errors. With noUncheckedIndexedAccess: 10 errors, at PayoffRunway.tsx:44, plans.ts:25 and 26, and export.ts:161, 164, 165, 166, 190, 191 and 192. All read in bounds today, so none is a live bug. noUnusedLocals, noUnusedParameters, noImplicitReturns, noFallthroughCasesInSwitch, noPropertyAccessFromIndexSignature and noImplicitOverride give 0 errors each and 0 extra together, also with .next/types included. exactOptionalPropertyTypes gives 1 (page.tsx:178). With the fix applied in a copy: tsc 0, verify.mjs PASS 180, next build ok, First Load 125 kB; getPovertyLine returned the same value before and after for 0, 1, 6, 7, 20, -3, 1.9, NaN, Infinity, '3', undefined and null, and the added throw was never reached.

## Required

An indexed read that can be undefined is typed that way in a tool that does money arithmetic, so a table or loop change that misses fails the build instead of producing NaN.

## Reproduce

Nothing shows in the app, because every read is in bounds today. The read with money behind it is the poverty-line lookup for the IBR estimate: on Plans, 'People in your household' offers 'Just me' to '8 people or more', and getPovertyLine (plans.ts:23-27) reads rows 1 to 6 of the table and adds a fixed step above 6. To reproduce the finding on a scratch branch: 1. Add "noUncheckedIndexedAccess": true to compilerOptions in tsconfig.json. 2. Run `npx tsc --noEmit`: 10 errors at the lines listed in measured (main gives 0). 3. Repeat with each of the other six flags for 0 errors each, and with exactOptionalPropertyTypes for 1.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "DX-09"`.

## Fix

Turn on the flag and the six that cost nothing, then guard the ten reads. Skip exactOptionalPropertyTypes.
tsconfig.json, after "strict": true:
```json
"noUncheckedIndexedAccess": true,
"noUnusedLocals": true,
"noUnusedParameters": true,
"noImplicitReturns": true,
"noFallthroughCasesInSwitch": true,
"noPropertyAccessFromIndexSignature": true,
"noImplicitOverride": true,
```
src/components/charts/PayoffRunway.tsx:43-45:
```ts
const ro = new ResizeObserver(([entry]) => {
  if (entry) setWidth(Math.round(entry.contentRect.width));
});
```
src/data/plans.ts:23-27, throwing rather than defaulting, because a 0 would silently raise an IBR payment:
```ts
export function getPovertyLine(householdSize: number): number {
  const n = Math.max(1, Math.floor(householdSize || 1));
  const row = POVERTY_2026[Math.min(n, 6)];
  if (row === undefined) throw new Error(`No 2026 poverty line for household size ${n}`);
  return n <= 6 ? row : row + (n - 6) * POVERTY_INCREMENT;
}
```
src/lib/export.ts, top of the loop at line 158 (one guard clears all seven export.ts errors):
```ts
const older = ordered[i - 1];
const newer = ordered[i];
if (!older || !newer) continue;
```

## Severity

No borrower is affected today: all ten reads are in bounds, and getPovertyLine returned the same value for every input the skeptic tried. It is compiler hardening against a future edit to a table or loop that feeds the money figures.

## Verification

Confirmed by 1 of 1 skeptic (P3 review lens), who reproduced all 10 errors at the exact lines on a copy of main and applied the fix: tsc 0, verify 180 of 180, build ok.
