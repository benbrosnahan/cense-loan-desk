# DX-10: No Node version declared

**P3** · effort S · Testing and maintainability

The repo declares no Node version and verify.mjs only runs because Node guesses its compiled files are ES modules, so builds and the dollar-figure checks can move to an untested Node release unnoticed; borrowers see no effect today.

| | |
|---|---|
| Who it hurts | No borrower is affected directly. The author or a contributor can build, or run the harness that checks the dollar figures, on a Node major nobody tested, and a Vercel default change could move the next deploy to another major with no record of what worked; the warning on every verify run also teaches people to skim past the harness's stderr. |
| Standard | Node.js release schedule (v24 LTS supported to 2028-04-30, in Maintenance since 2026-10-20; v25 ended 2026-06-01; v26 Active LTS since 2026-10-28) and Node.js ES module type resolution (syntax detection on by default only from v22.7.0 and v20.19.0) |
| Where | Repository root and verify.mjs, on any laptop or CI that runs npm ci, next build or node verify.mjs, and in Vercel's build. No browser state or viewport is involved. Reproduced on Node 25.9.0, 24.13.0 and 24.22.2. |
| Code | [`package.json:4-5`](../../package.json#L4-L5), [`verify.mjs:49-54`](../../verify.mjs#L49-L54), [`verify.mjs:84-86`](../../verify.mjs#L84-L86), [`README.md:31-36`](../../README.md#L31-L36) |

## Measured

package.json has no engines field, and the repo has no .nvmrc, .node-version, .tool-versions, CI config, vercel.json or .vercel; the README's 'Run it' section names no Node version. Next 14.2.35 accepts any Node from 18.17.0 (engines in node_modules/next/package.json). The Vercel project's Node setting is not visible from the repo, and Vercel's docs list 26.x as the default. The audit machine runs v25.9.0, past its 2026-06-01 end of life; that is the auditor's machine, not evidence of what the author or Vercel uses. On 25.9.0, 24.13.0 and 24.22.2, node verify.mjs exits 0 with PASS 180 FAIL 0 and writes one [MODULE_TYPELESS_PACKAGE_JSON] warning to stderr naming .verify/lib/calc.js, because .verify has no package.json. With --no-experimental-detect-module it exits 1 with ERR_REQUIRE_CYCLE_MODULE on all three. Node's docs say detection is on by default only from v22.7.0 and v20.19.0, so older Node that Next still accepts should fail the same way; that rests on the docs and the flag, not on a run with old Node. With only the one-line fix, all three versions exit 0 with PASS 180 and no warning, with and without the flag. Clean installs pass npm ci, next build and verify on 24.13.0 and 24.22.2. With engines set to 24.x, npm on 25.9.0 prints an EBADENGINE warning and continues.

## Required

One declared Node LTS major that laptops and Vercel both build with (engines plus .nvmrc), and a verify.mjs that gives the same result whether or not Node's syntax detection is on: exit 0, PASS 180, no MODULE_TYPELESS line.

## Reproduce

Borrowers never see this, so there are no in-app steps. In a terminal at the repo root:
1. node -p "require('./package.json').engines" prints undefined; ls -a shows no .nvmrc, .node-version or .tool-versions; README.md:31-36 ('Run it') names no Node version.
2. node verify.mjs on Node 24 or 25 ends with 'PASS 180   FAIL 0', but stderr carries '[MODULE_TYPELESS_PACKAGE_JSON] Warning: Module type of file:///…/.verify/lib/calc.js is not specified and it doesn't parse as CommonJS.'
3. rm -rf .verify && node --no-experimental-detect-module verify.mjs; echo $? prints 1 after ERR_REQUIRE_CYCLE_MODULE. The flag turns off the syntax detection that Node only enables by default from 22.7.0 and 20.19.0. (.verify is generated and gitignored.)

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "DX-10"`.

## Fix

Check the Node.js Version in the Vercel project settings first, because engines overrides it. Then three small edits.

package.json, after "private": true at line 4:
```json
"engines": { "node": "24.x" },
```

.nvmrc at the repo root:
```
24
```

verify.mjs, right after the compile step that ends at line 54 (writeFileSync is already imported at line 59, and static imports are hoisted):
```js
// Mark the compiled output as ES modules so Node does not have to guess.
writeFileSync(".verify/package.json", '{"type":"module"}\n');
```

Pin 24.x if the Vercel project is on 24 or there is no reason to move: it is the only major tested here (npm ci, next build and node verify.mjs pass on 24.13.0 and 24.22.2) and it is supported to 2028-04-30. If the project is on 26.x, Vercel's current default, run those three commands on Node 26 first and pin 26.x instead. A 24.x pin makes npm on Node 25 print an EBADENGINE warning without failing. Nothing changes at runtime and nothing is sent anywhere.

## Severity

No borrower is affected: the live build and today's harness both work, and the risk reaches only the author or a contributor when the Node version under them changes. That is build and test hardening, so P3.

## Verification

Confirmed by 2 of 2 skeptics (P3 review lens, one per filed finding), reproduced on Node 25.9.0, 24.13.0 and 24.22.2.
