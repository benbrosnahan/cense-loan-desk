# UX-04: Answering a question changes the pick off screen

**P2** · effort S · UX and UI

Answering a Plans question changes the recommended plan and payment below the fold with nothing on screen or announced, so a phone user cannot tell their answer just moved the pick from Standard at $311 to Graduated at $139 a month.

## Measured

Example balances (8 loans, $28,101, all paid out before July 1, 2026), nothing answered yet, 375x812:
- After the Plans tab tap the page settles at scrollY 235 by 259ms. The 'Where we would start' box has its top at y=1030 (docTop 1265): 1.27 screens down, 218px below the fold, with all four questions above it (y=333, 547, 751, 890).
- Tapping 'Lowest monthly payment' changes the box from Standard '$311 a month' to Graduated '$139 a month, to start'. The tap scrolls by 0, the box is in no live region, and no toast appears.
- What changes on screen: the two chips' checked state and the hint line under them ('We will recommend on total cost, which is the safe default.' becomes 'Cash flow is tight and the monthly number matters most.'). The hint is a polite live region and is the only announcement; no live region names the plan.
- With each control scrolled to the centre: goal chip, plan name at y=1135; employer chip, y=924 (both off screen); income field, name and amount at y=722-802; household, y=583-663 (on screen, with no on-screen keyboard emulated).
- Laptops, after the tab tap: the box's top is at y=821 at every window height and the plan name's bottom at y=924, so the name is clipped at 1440x900 and 1536x864, fully below the fold at 1366x768 and 1280x720, and visible at 1920x1080.
- Page height at 375: 4,758px with nothing answered, 4,813 after the goal tap, 4,839 with a plan chosen, so about six screens (5.86 to 6.04).

## Required

When an answer changes the recommended plan or payment, the borrower sees the new pick where they gave the answer, or is pointed to it, and a screen-reader user hears it once the input settles.

## Reproduce

1. In a fresh browser window at phone size (375x812), open the app and click 'Look around with example loans'.
2. Tap Plans in the section bar. The page scrolls to 'Four questions, so the plans fit you'; the 'Where we would start' box is below the bottom edge of the screen.
3. Tap 'Lowest monthly payment'. On screen, only the chips and the grey hint line under them change.
4. Scroll down. The box now reads Graduated, $139 a month, to start; before the tap it read Standard, $311 a month.
These steps were re-checked through the example loans on the local build: same figures, and the box's top lands at the same on-screen position after the tab tap.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "UX-04"`.

## Fix

Show the current pick inside the questions card, pinned to the bottom of the screen while the card is in view, and announce it to screen readers once input settles. Three files.

```tsx
// src/app/page.tsx: add rankPlans to the @/lib/calc import (lines 32-39) and money to the @/lib/utils import (line 47).
// After selectedEstimate (line 203), above the hydrated early return:
const topPick = useMemo(() => {
  if (!loans.length) return null;
  const t = rankPlans(estimates, buildContext(loans, profile)).ranked.find((r) => r.isTopPick);
  // Same guard as the recommendation box (PlansPanel.tsx:342).
  return t && t.estimate.monthlyPayment !== null ? t.estimate : null;
}, [estimates, loans, profile]);
const pickText = topPick
  ? `${PLAN_META[topPick.id].name}, ${money(topPick.monthlyPayment)} a month${topPick.id === "graduated" ? ", to start" : ""}`
  : "";
// Announce once typing settles, so $5, $52 and $520 do not each read out a plan.
const [announced, setAnnounced] = useState("");
useEffect(() => {
  const t = setTimeout(() => setAnnounced(pickText), 600);
  return () => clearTimeout(t);
}, [pickText]);

// Inside the questions Card, after the questions block (line 777), before </Card> (line 778):
{topPick && (
  <p className="sticky bottom-2 mt-6 rounded-2xl bg-brand-light px-4 py-3 text-sm font-semibold">
    Right now: {PLAN_META[topPick.id].name}, <Money value={topPick.monthlyPayment} /> a month
    {topPick.id === "graduated" && ", to start"}.{" "}
    <a href="#pick" className="text-navy underline underline-offset-2">See why</a>
  </p>
)}
<p className="sr-only" aria-live="polite">
  {announced && `Our pick is now ${announced}.`}
</p>
```

// src/components/plans/PlansPanel.tsx:344, a target for the link:

```css
/* src/app/globals.css, inside the html rule (lines 5-8), so the pinned line never covers a focused field: */
scroll-padding-bottom: 6rem;
```

The existing scroll-padding-top: 5rem (globals.css:7) already lands the #pick jump below the 74px section bar. <Money> keeps the amount under Hide amounts, and ', to start' keeps Graduated's figure labelled as a starting payment, as the box at PlansPanel.tsx:356 does.

## Severity

Nearly every phone borrower who answers the first two questions (goal and employer) meets this on every visit, and laptop windows 720 to 900px tall show the plan name clipped or below the fold. Nothing shown is wrong and the recommendation box explains its reason once reached, so it is a bounded feedback defect rather than a wrong answer, but the form's main result changes unseen, which keeps it above polish.

## Verification

Confirmed by 2 of 2 skeptics (reproduce, standards); the standards skeptic would rate it P3.

Standard: the standards skeptic rejected the WCAG 4.1.3 citation, citing W3C's Understanding document (the criterion does not force new status messages, and the recommendation is result content); dropped here. Both skeptics moved the member's second idea, collapsing answered questions on return visits, out of this fix.

Fix choice: the member's pinned line with both skeptics' corrections: <Money> so Hide amounts covers it; ', to start' for Graduated as PlansPanel.tsx:356 does (the README's sweep records the unlabelled starting payment as a bug); the box's priced-pick guard (PlansPanel.tsx:342); a real #pick target; and scroll-padding-bottom so the line never covers a focused field. A goal tap now produces two polite announcements: the existing hint, then the pick.
