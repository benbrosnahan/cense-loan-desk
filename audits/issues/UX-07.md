# UX-07: Hide amounts leaves figures readable

**P2** · effort S · UX and UI

'Hide dollar amounts' blurs the headline figures but leaves the income, extra-payment and loan-form fields, the 'costs $X more' sentences on Plans and the plan dropdown's payments readable (and, in Safari's engine, the chart's axis amounts), so a borrower who turns it on in public still shows those figures to anyone beside them.

## Measured

Audit 8-loan fixture (income 52,000, extra 100, Standard selected), Hide turned on with a real click. The .amt blur reaches 14, 18, 46 and 8 elements on Loans, Plans, Payoff and Records with every disclosure open, but computed filter is none on: Plans by default, #income showing 52,000 and three 'Not picked' sentences with $3,346, $5,392 and $7,654 (other goals show more: lowest_payment $172, $95, $2,046, $78 and $4,307; forgiveness and unsure $94 and $17). Payoff by default, #extra showing 100 and the pressed $100 preset (aria-pressed true); with the disclosure open, #planswitch shows 'Standard, $311 a month' and its options Graduated $139, IBR $234 and RAP $217. Edit form: #balance 3,500 and #principal 3,500; the Add form shows a typed balance (12,345). Mac WebKit: the chart's axis text '$30k' and '$15k' paints sharp although its computed filter is blur(5.46px); Chromium blurs it, and HTML .amt blurs in both engines. Loans list, expanded rows and Records: 0 readable figures. Not counted: the fixed rule text 'Requires more than $30,000 in Direct Loans', the $0, $10 and $50 rule copy, unpressed preset labels, the sr-only live output and #rate (4.99). The toggle's name is sr-only text, aria-pressed flips and the icon gains a slash; no toast. Corrected fix beds: with the value-only CSS, #income and #extra compute color rgba(0, 0, 0, 0) with a 6.72px text-shadow on screen, the axis text computes visibility hidden, focus shows the value (typing 520,007 works), and under print media every field and the axis print exactly as shipped (ink 1169/235 income, 883/149 extra, 172/84 axis).

## Required

With Hide on and no field focused, no figure about this borrower is readable on screen in Chromium or WebKit: the five dollar fields, the cost-gap sentences, the plan select's options and the chart axis are concealed. A focused field shows its value so typing still works, printing still shows every figure (globals.css:154), and #rate and the fixed plan-rule text stay readable.

## Reproduce

1. Open http://localhost:3100 and click 'Look around with example loans' (the example set has the same amounts as the audit fixture).
2. Tap the eye button at the top right ('Hide dollar amounts'). 'You owe' blurs.
3. Open Plans. Pick 'Pay the least overall' and 'Nonprofit', type 52000 in 'Yearly income, before tax', then tap outside the field. It still reads 52,000, and the sentences under the other plans ('Not picked because it ... costs $3,346 more overall', also $5,392 and $7,654) are sharp while the figures above them blur.
4. Click 'Use Standard as my plan', open Payoff, type 100 in 'Extra each month' and tap outside: the field reads 100 and the $100 chip is highlighted. Open 'See how a different plan changes this': the select reads 'Standard, $311 a month' and its list shows Graduated $139, IBR $234 and RAP $217.
5. In Safari, the Payoff chart's axis labels ($30k, $15k) stay sharp.
6. Open Loans, tap the first loan, then Edit: Balance reads 3,500; open 'Add more detail' and Principal reads 3,500.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "UX-07"`.

## Fix

Conceal the five dollar fields and the WebKit axis labels with screen-only CSS, blur the figures inside the 'Not picked' sentences, and drop the figure from the plan options while hidden. Leave the eye button as it is.

1. src/components/shared/ui.tsx:324, inside AffixInput's cn(). One line tags #income, #extra, #balance, #principal and #minp, and not #rate (it has a % suffix):
```tsx
prefix === "$" && "amt-field",
```

2. src/app/globals.css, after line 78. Screen only, so printing with Hide on still shows every figure as line 154 intends. Only the value is blurred, so the border, the $ and the caret stay usable, and a focused field shows its value:
```css
@media screen {
  .amounts-hidden .amt-field:not(:focus) {
    color: transparent;
    text-shadow: 0 0 0.42em #275b2d;
  }
  /* WebKit reports a blur on SVG text but does not paint it. */
  .amounts-hidden svg text.amt { visibility: hidden; }
}
/* Forced colors overrides color and text-shadow. */
@media screen and (forced-colors: active) {
  .amounts-hidden .amt-field:not(:focus) { filter: blur(0.42em); }
}
```

3. src/components/plans/PlansPanel.tsx:190. Keep whyNot a string (verify.mjs:483 checks its length) and wrap the figures at render:
```tsx
{plan.whyNot.split(/(\$[\d,]+)/).map((part, i) =>
  i % 2 ? <span key={i} className="amt tnum">{part}</span> : part
)}
```

4. A native option cannot be blurred, so drop the figure while hidden. Add `hideAmounts: boolean` to RankingPanel's Props and arguments (RankingPanel.tsx:47-53 and :77-83), pass `hideAmounts={hideAmounts}` at page.tsx:807, and at RankingPanel.tsx:369:
```tsx
{PLAN_META[e.id].name}
{hideAmounts ? "" : `, ${money(e.monthlyPayment!)} a month`}
```

## Severity

Every borrower who turns Hide on and then opens Plans (income and the cost-gap sentences are readable by default), Payoff (the extra amount) or a loan's Edit form hits this, every time and at every width, and in WebKit the chart's axis amounts stay sharp too. No figure is wrong and nothing leaves the device: it is a privacy control doing less than its label and the code's own comments promise, a real but bounded defect.

## Verification

Confirmed by 8 of 8 skeptics across 4 filings (reproduce and standards on each); all 8 kept P2.

<details><summary>Dissent and notes</summary>

No severity dissent. Every filing undercounted the leak. The dx and bp text-node walkers cannot see input values: dx missed #income and #extra, bp reported #extra as empty because its regex needed a $ or a comma (it shows 100), and the Edit form's #balance and #principal were missed by dx, a11y and bp (ux listed #balance only). The a11y filing's 'Loans is clean' holds only with no form open. The WebKit axis leak was found only by skeptics (dx reproduce, a11y standards, a11y reproduce), and a computed-filter test cannot catch it. The plan select leaks only after a closed disclosure is opened (ux standards and dx reproduce skeptics); the dx filing lists 3 option figures because its probe's slice(0, 8) cut off the ninth node, $217. The ux filing's 'icon only, aria-label null, no toast or other status' was judged weak by both ux skeptics: sr-only text is a valid accessible name, aria-pressed with a fixed label is the APG toggle pattern, and the icon and blur do change. The ux reproduce skeptic still proposed a visible 'Hide amounts' label from sm up, a title and a toast; the ux standards skeptic said leave the button alone, since the filed visible Hide/Show text made the page 388 to 389px wide at a 375 viewport. Fix disagreements: -webkit-text-security: disc on the dollar fields (ux skeptics, built in Chromium only) against a value-only blur (a11y skeptics, Chromium and Mac WebKit) against filter: blur on the whole input (dx standards and bp, Chromium; it blurs the border and paints over the $). For the plan select, dropping the figure from the option text (dx skeptics) against blurring the select until focused (a11y skeptics, bp), which leaves the open native list readable. The bp filing's print override (.amounts-hidden .amt-field { filter: none }, also in the dx standards fix) loses on specificity to the :not(:focus) rule, 0,2,0 against 0,3,0, so as written it would blur the fields on paper (bp reproduce skeptic). The ux filing's whyNot-as-parts change fails verify.mjs 176 of 180, and its input[inputmode] mask also hides the rate.

Fix choice: the a11y skeptics' value-only blur, because it was built and checked in Chromium and Mac WebKit, keeps the border, $ and caret usable, avoids user-select: none on an input, and leaves the value available to screen readers (the toggle hides figures from onlookers, as globals.css:70-71 says). Then the bp and dx standards skeptics' one-line AffixInput tag, so all five dollar fields are covered and #rate is not, and the dx skeptics' option-text change, because an open native option list cannot be blurred. Scoping to @media screen keeps today's print output without a print override. The pieces were built separately, not as one patch: the a11y reproduce skeptic built the CSS with a class on each field and checked the screen scoping by injection; the bp standards skeptic built the AffixInput line (blur computed on all four rendered dollar fields, #rate and #nickname clear); the dx skeptics built the sentence split and option change (verify.mjs 180 of 180, journey 18 of 18). The forced-colors rule was injected, not compiled, and blurs the whole field in that mode. -webkit-text-security: disc on the same selector is a one-rule alternative, but it was built in Chromium only and its effect on screen readers was not checked.
Residual, the author's call: the highlighted preset chip and the slider thumb still show the extra amount. With hideAmounts now in RankingPanel, `extra === p && !hideAmounts ? "border-navy bg-navy text-white" : "border-slate-300 bg-white text-slate-900 hover:border-navy"` at RankingPanel.tsx:284-287 drops the highlight and keeps aria-pressed (built by the dx reproduce skeptic: the chip is no longer highlighted). Blurring only the pressed chip would reveal it by elimination.
Related: A11Y-01, where the header overflows at 320 to 360px and only 3px of this eye button is on screen at 320, so the toggle itself is hard to reach on the smallest phones.
Not tested: iOS Safari, Firefox, Android.
