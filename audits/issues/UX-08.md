**P2** · effort S · UX and UI

After 'Look around with example loans', the only 'example' marker is a banner that scrolls away on the first tab tap and is left off the printout and the spreadsheet, and a snapshot saved from the examples stays in the borrower's dated record, so demo figures can be printed, filed as 'your evidence' and later show up as eight loans 'removed from your list'.

## Measured

375x812, examples loaded through the real button, toast waited out. After any tab tap scrollY is 349 and the banner box top is -265 (its text line -252); at 375 and 1440 no text node in the viewport contains 'example' on Plans, Payoff, Records or Loans, and the banner is the only mention on the page. Plans heading: 'All 4 plans open to you'; the recommendation card has no marker. Print at 0.4in: 2 pages, the banner display none (no-print), no 'example' in the PDF text. Loans xlsx: A1 'Cense Loan Desk — your loans', A3 'Keep this file. If a balance or rate changes and nobody can explain why, this is your evidence.', no 'example'. Snapshot card: '#1 ... $28,101, 8 loans on record', unmarked, no delete control. After adding one real loan (it replaces the examples) and saving again: 8 'removed from your list' rows and 1 'added' row; the history xlsx 'What changed' sheet carries 8 'Loan removed' rows and no 'example'. The only removal is Loans > Clear my data > Clear saved records, which clears every record. 'You owe $28,101' is not an unmarked leak in practice: after a tab tap it is off screen too (bottom -64), and at the top it sits directly under the banner. Fix bed as filed (both skeptics): the label is in the viewport on all 4 tabs, the print contains 'example', A1 is 'EXAMPLE DATA, not your loans' and Save is disabled; the sticky bar grows from 74px to 99px, past html scroll-padding-top of 80px; snapshots saved before the fix still show until a load filter removes them.

## Required

While example loans are loaded, 'example' is visible on every tab without scrolling back up, on the printout and in the spreadsheet; untouched example loans cannot enter the dated record, and example-only snapshots already saved are removed, while anything the borrower typed is kept.

## Reproduce

1. Open http://localhost:3100 with no saved data and click 'Look around with example loans'. Wait for the 'Example loans loaded' toast to go.
2. Tap Plans, Payoff or Records. The amber 'These are example loans, not yours.' banner is now above the sticky bar and nothing on screen says 'example'; Plans reads 'All 4 plans open to you'.
3. On Loans, click 'Print one page': the preview has no banner and no 'example'.
4. Click 'Download as a spreadsheet': A1 reads 'Cense Loan Desk — your loans' and A3 ends 'this is your evidence.'
5. Open Records and click 'Save today's snapshot': card #1 shows $28,101 and '8 loans on record', with no marker and no delete control.
6. On Loans, click 'Add my own' in the banner, save any loan, then Records > 'Save today's snapshot': the new card lists 8 'removed from your list' rows and 1 'added'. Download the history spreadsheet: its 'What changed' sheet has 8 'Loan removed' rows. Only Loans > Clear my data > Clear saved records removes #1, and it removes every record.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "UX-08"`.

## Fix

Mark example mode wherever the data is read or leaves the app, and keep untouched examples out of the dated record.

1. src/lib/storage.ts: one shared test, field by field (RES-01's isUntouchedExample), so an example the borrower has typed over counts as theirs. An edit keeps the seed- id (LoanForm.tsx:205), so the id test alone would treat their own numbers as examples:
```ts
import { SEED_LOANS } from "@/data/seed";

export const isUntouchedExample = (l: Loan) => {
  const s = SEED_LOANS.find((x) => x.id === l?.id);
  return !!s && (Object.keys(s) as (keyof Loan)[]).every((k) => s[k] === l[k]);
};
export const onlyExamples = (loans: unknown): boolean =>
  Array.isArray(loans) && loans.length > 0 && loans.every(isUntouchedExample);
```

2. page.tsx:142, drop example-only snapshots already saved:
```ts
setSnapshots(snapshotStore.load().filter((s) => !onlyExamples(s?.loans)));
```

3. page.tsx:436, print the banner: remove `no-print` from the wrapper div and add it to the 'Add my own' button's className (:446).

4. Inside the sticky bar, above the <nav> at page.tsx:514, using the banner's own `example` flag:
```tsx
{example && (
  <p className="example-label mb-1.5 text-center text-xs font-semibold text-amber-900">
    Example loans, not yours
  </p>
)}
```
and after globals.css:8, reserve room for the taller bar (99px against today's 5rem):
```css
html:has(.example-label) { scroll-padding-top: 6.5rem; }
```

5. export.ts:99, import onlyExamples from ./storage beside diffSnapshots and mark the sheet:
```ts
const rows: Row[] = [
  ...(onlyExamples(loans) ? [["EXAMPLE DATA, not your loans"]] : []),
  ["Cense Loan Desk — your loans"],
```

6. HistoryPanel.tsx: add `const example = onlyExamples(loans);` and use `disabled={!loans.length || example}` at :67. While example is true, add 'Snapshots are off while example loans are loaded.' to the caption at :78-83 (the reproduce skeptic's built copy) and replace 'Save one now to start the record.' at :93 with 'Add your own loans, then save one to start the record.'

## Severity

Affects borrowers who take 'Look around with example loans', the path the first-run card offers anyone not near their studentaid.gov login, each time they change tabs, print, export or save a snapshot before adding their own loans. The figures are right for the example set and the banner is back at the top on every reload, but the spreadsheet calls demo data 'your loans' and 'your evidence' and a demo snapshot stays in the dated record with no way to remove it alone: misleading statements with no wrong number.

## Verification

Confirmed by 2 of 2 skeptics (reproduce, standards), both keeping P2; both built the filed fix and it passed its own test idea.

<details><summary>Dissent and notes</summary>

No severity dissent. Both skeptics found the filed impact overstated: 'You owe $28,101' is off screen after a tab tap too, and it sits directly under the banner, so it reads unmarked only in a narrow scroll band (scrollY 178 to 285 by the reproduce skeptic's measure; 120 to 284 at 375 and 136 to 292 at 1440 by the standards skeptic's). Same-session confusion is the weak part; the printout, both spreadsheets and the polluted record are the strong part. Fix additions rather than disagreements: the reproduce skeptic passed a boolean into the export and flagged the 99px bar against the 80px scroll padding; the standards skeptic moved isExample into lib/storage.ts and added the load filter for snapshots already saved; both said the Records empty-state copy must change beside a disabled button.

One deviation from the skeptics' builds: both used the id test (every id starts with 'seed-') for the load filter and the disabled Save. The first-run card invites borrowers to 'swap in your own numbers later' (page.tsx:412-413), and an edited example keeps its seed- id (LoanForm.tsx:205), so the id test would delete snapshots of a borrower's own typed balances on the next load, with no message, and block them from saving new ones. This fix uses RES-01's field-by-field test for the record and the export, and keeps the banner's id test for the on-screen label and the printed banner so those always agree with the banner. The field-by-field version was not built; the id version passed in both skeptics' scratch builds. onlyExamples tolerates a malformed stored snapshot, which RES-07 covers.
Coordination: RES-01 (P1) replaces isExample with the same isUntouchedExample and a counted banner; define it once in lib/storage.ts, and once RES-01 lands show the bar label when exampleCount > 0. UX-11 covers deleting a single snapshot and RES-04 covers Clear my data. Printing the banner adds a block to page 1 while examples are loaded; in the reproduce skeptic's combined bed with UX-09's spacing the example list still printed one page at 0 to 0.4in and two at 0.5in. The :has() rule leaves older browsers at today's 5rem, which only matters for keyboard focus under the taller bar.
Residual: a snapshot saved after some, not all, examples were edited keeps the untouched rows, so the next real snapshot still lists them as removed.
Not tested: iOS and Android browsers, Firefox.
