# UX-09: "Print one page" prints two

**P3** · effort S · UX and UI

'Print one page' prints two pages for almost every borrower with more than one loan and puts no date on the printout, so someone keeping a paper record gets a second sheet of boilerplate (in Safari's engine, with their last loan on it) and an undated copy unless the browser adds a header.

## Measured

Chromium, Letter, 0.4in margins, backgrounds off, audit fixture (240 PDFs; pypdf and the /Count entry agree): 1 loan prints 1 page, 2 to 14 loans 2 pages, 15 to 24 loans 3. A4 at 0.4in: 1 to 2 loans 1 page, 3 to 16 loans 2, 17 to 24 loans 3. At 8 loans the count stays 2 at margins 0, 0.25in, 0.4in, 0.5in, 1cm and 1in, at viewports 375 to 1920, with or without backgrounds, and on the live site (2 loans also print 2 there); one post-cutoff loan among the 8 also gives 2, and the example-loans path gives 2. A single loan with accrued interest prints 2 pages on Letter; only a loan whose balance equals its principal fits on 1. Layout at 8 loans: 1486px of content against 979px printable, with main keeping 112px of bottom padding (pb-28); the late-fee notice sits at 994-1120 and the footer at 1176-1374. At Letter 0.25in to 1cm all 8 loans and the totals are on page 1 and page 2 holds the whole late-fee notice and the footer, with no dollar figure; the notice splits title from body only at margin 0 (the filed PDF, Puppeteer's default) and at A4 0.4in, and at 0.5in the eighth loan also moves to page 2. With 2 or 3 loans page 2 holds only the 'Built by Cense' line. Loan rows never split across pages. Mac WebKit (NSPrintOperation): 8 loans print 2 pages at 0.25in to 0.5in with the eighth loan row ($2,123) opening page 2, and 3 pages at 1in with the third blank; 2 loans print 2 pages with page 2 blank. The printed content has no date; Chrome adds one ('11/2/26, 1:37 PM') only through its headers option. Plans with backgrounds off: the top-pick card loses its fill and its white text prints #ABABAB on white, 2.30:1 for 'Standard' and '$311', the reason 2.19:1, 'a month' 2.09:1, the disclaimer 1.99:1, the eyebrow 1.90:1; the plan and $311 also print dark in the list card below. page.pdf() itself takes a median of 65 to 73ms.

## Required

The button promises nothing the printout cannot keep at every list length; the printed content carries the date it was printed; the common 8-loan list fits one Letter page at 0.25in to 0.5in margins in Chromium and WebKit; text in the printed top-pick card is 4.5:1 or more.

## Reproduce

1. Open http://localhost:3100 and click 'Look around with example loans' (8 loans).
2. On Loans, scroll to 'Keep a copy' and click 'Print one page'.
3. In Chrome's print dialog (Letter, default margins, background graphics off) the preview has 2 pages: page 1 holds the summary and all 8 loans, page 2 the 'Missing a payment does not cost a late fee' notice and the footer. Untick 'Headers and footers': no date appears anywhere. In Safari, the last loan row opens page 2.
4. Open Plans and print from the browser with background graphics off: the green 'Where we would start' card loses its fill, and 'Standard' and '$311' print light grey.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "UX-09"`.

## Fix

1. page.tsx:641, rename the button to 'Print'. No stylesheet keeps 10 or more loans, a post-cutoff notice or 1in margins on one page, so the label must not promise a page count.

2. Date the printout when it is printed. With the other hooks in page.tsx (before the early return at :294):
```tsx
const printedRef = useRef<HTMLParagraphElement>(null);
useEffect(() => {
  const stamp = () => {
    if (printedRef.current)
      printedRef.current.textContent = `Printed ${new Date().toLocaleDateString("en-US", { dateStyle: "long" })}`;
  };
  window.addEventListener("beforeprint", stamp);
  return () => window.removeEventListener("beforeprint", stamp);
}, []);
```
and as the last child of the Summary section (page.tsx:453-504):
```tsx
<p ref={printedRef} className="mt-2 hidden text-sm text-slate-700 print:block" />
```

3. Keep the common list on one sheet: add `className="no-print"` to the late-fee Notice (page.tsx:621) and `no-print` to the privacy and 'Built by Cense' footer paragraphs (:840 and :846), keeping the not-advice line, and extend the print block at globals.css:151-155:
```css
@media print {
  .no-print { display: none !important; }
  body { background: #fff; }
  .amounts-hidden .amt { filter: none; }
  main { min-height: 0 !important; padding-bottom: 0 !important; }
  main section[aria-label="Summary"] { padding-top: .75rem !important; }
  main ul > li > button { padding-top: .25rem !important; padding-bottom: .25rem !important; }
  main li { break-inside: avoid; }
  main footer { margin-top: .75rem !important; padding-top: .5rem !important; }
  /* Keep the top-pick card's fill so its white text stays readable on paper. */
  .bg-navy { -webkit-print-color-adjust: exact; print-color-adjust: exact; }
}
```

## Severity

Everyone who prints a list of 2 to 14 loans on Letter, or a single loan with accrued interest, gets two sheets from a button that promises one. But in Chrome at default settings every figure is on page 1, page 2 is the late-fee notice and the footer, and Chrome's default header prints the date; in WebKit the last loan row moves to page 2 without being lost. No figure is wrong or missing, so this is polish, though the in-page date matters to anyone who prints with headers off.

## Verification

Confirmed by 4 of 4 skeptics across 3 filings (reproduce and standards on the ux filing, one P3 review each on the perf and a11y filings); 3 rate it P3, the ux reproduce skeptic kept P2.
