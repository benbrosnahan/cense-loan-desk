# UX-10: Sections are not URLs: Back exits, reload resets

**P2** · effort S · UX and UI

Sections are not in the URL, so Back takes a borrower out of the app instead of to the previous section, and a reload or a saved link always reopens on Loans.

| | |
|---|---|
| Who it hurts | A borrower who swipes back from Payoff to re-read the plans is thrown out of the app mid-decision, and one who reloads or reopens a bookmarked section lands on Loans and has to find their place again; their loans and records are kept. |
| Standard | No WCAG criterion requires a URL per section, and SC 2.4.2 Page Titled is not failed, because WCAG counts a one-URL app as one web page. Nielsen heuristic 3, user control and freedom: the section bar marks the open section aria-current="page" (page.tsx:522), which tells people each section is a page they can go Back to. |
| Where | All four sections (Loans, Plans, Payoff, Records) once loans are saved, at every width. Measured in Chromium at 375x812, 412x823, 768x1024, 1280x800, 1280x900 and 1440x900, both in a fresh tab and after arriving by a link from another page. Not tested in iOS Safari or Firefox. |

## Measured

With 8 saved loans, tapping Plans, Payoff and Records leaves the URL at / and adds no history entry: history.length is 2 before and after in a fresh tab, and 3 before and after when the app was opened from a link on another page. The app makes 0 pushState calls; the only replaceState is Next's own at load. One Back from any section leaves the app for the previous page (about:blank in a fresh probe tab) at every width tried. Reload on Payoff or Records returns to Loans. /#plans, /#payoff, /#records, /?tab=plans and /?view=payoff all open Loans, and /plans, /payoff and /records return 404. Forward after leaving restores the section (Payoff, Records) when the browser kept the page in its back-forward cache, and returns to Loans when it did not. document.title is identical in every section.

## Required

Back returns to the section visited before and leaves the app only from the first one; Forward walks back in; reload keeps the current section; #plans, #payoff and #records open that section on this device when loans are saved and are dropped when there are none. Only the section name goes in the URL, never a figure, and a fragment is never sent to a server.

## Reproduce

1. Open any web page, then open http://localhost:3100 in the same tab and click 'Look around with example loans'.
2. Tap Plans, then Payoff. The address bar stays at http://localhost:3100/.
3. Press the browser's Back button, or swipe back on a phone. The browser leaves Loan Desk for the page you came from instead of showing Plans.
4. Press Forward to return, tap Payoff and reload. The app opens on Loans.
5. Open http://localhost:3100/#payoff. The app opens on Loans.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "UX-10"`.

## Fix

Put the section in the URL fragment with the History API. A fragment never leaves the device, and nothing new is installed. All in src/app/page.tsx; put the two new effects next to the existing ones, above the `if (!hydrated)` return at line 294.
```tsx
// After TABS (line 77). Loans has no fragment. A Map, not an object literal:
// with an object, /#valueOf resolves through Object.prototype and crashes the page.
const HASH_TO_TAB = new Map<string, Tab>([
  ["plans", "plans"],
  ["payoff", "order"],
  ["records", "history"],
]);
const TAB_TO_HASH: Partial<Record<Tab, string>> = { plans: "plans", order: "payoff", history: "records" };
const urlWithoutHash = () => window.location.pathname + window.location.search;

// Mount effect, replacing line 140. A section link only counts once loans exist.
const saved = loanStore.load() ?? [];
setLoans(saved);
const linked = HASH_TO_TAB.get(window.location.hash.slice(1));
if (linked && saved.length) setTab(linked);
else if (linked) window.history.replaceState(null, "", urlWithoutHash());

// New effect: Back and Forward walk the sections.
useEffect(() => {
  const onPop = () => {
    const hash = window.location.hash.slice(1);
    const target = hash === "" ? "loans" : HASH_TO_TAB.get(hash);
    if (!target) return; // the skip link's #main, for one
    setTab(target);
    setAdding(false);
    setEditing(null);
  };
  window.addEventListener("popstate", onPop);
  return () => window.removeEventListener("popstate", onPop);
}, []);

// New effect: no loans means first run, whatever the history entry says.
useEffect(() => {
  if (!hydrated || loans.length) return;
  setTab("loans");
  if (HASH_TO_TAB.has(window.location.hash.slice(1)))
    window.history.replaceState(null, "", urlWithoutHash());
}, [hydrated, loans.length, tab]);

// goTo (line 205), before setTab(next). Re-tapping the open section adds nothing.
if (next !== tab) {
  const hash = TAB_TO_HASH[next];
  window.history.pushState(null, "", hash ? `#${hash}` : urlWithoutHash());
}

// clearLoans, after setTab("loans") at line 264.
window.history.replaceState(null, "", urlWithoutHash());
```

## Severity

Hits every borrower with saved loans who presses Back, swipes back or reloads while in Plans, Payoff or Records, which is routine on a phone. They lose their place, but no figure is wrong, no data is lost and the sticky section bar gets them back in one tap, so it is a real but bounded defect.

## Verification

Confirmed by 7 of 8 skeptics across 4 filings (reproduce and standards on each). The eighth, agentic-no-url-state's standards skeptic, reproduced the Back and reload behaviour but refuted that filing's WCAG and agent claims, and a tie-breaker kept the filing. Every skeptic kept P2.

<details><summary>Dissent and notes</summary>

Standard and scope: agentic-no-url-state cited WCAG 2.2 SC 2.4.2 as advisory and said an agent cannot tell which section is open. Its standards skeptic refuted both: by WCAG's own definition this one-URL app is a single web page whose title describes it (F25 does not apply, and G127 concerns separate pages), and the missing aria-current is a tool artifact, because CDP, Puppeteer and Playwright 1.64.1 drop it on a control page too while the platform accessibility mappings expose it; each section's first heading also names it. The tie-break run showed the same omission on its control page, and the filing is kept here for the Back, reload and link behaviour only. Wording: 'about:blank' is only the probe's blank start tab, so the accurate claim is that Back leaves the app for the previous page; 'their place does not survive' is too strong for Forward in Chromium, which restored the section from the back-forward cache, though a reload or a new visit does land on Loans. The SEO filing's Google reference is a loose paraphrase: Google's URL-structure guidance says not to use fragments to change content and to use the History API for crawlable URLs. Fragments are still right here, because only personal state sits behind them and a crawler with no saved loans never sees it. 'Shareable' means bookmarkable on the same device; anyone else who opens the link gets first run. Fixes: every filed fix had a measured regression. The UX filing's `setTab(e.state?.tab ?? "loans")` moved a keyboard user from Plans or Payoff to Loans when they used the skip link (popstate fires with null state) and added a history entry on every repeat tap. The resilience filing's ignored the first history entry, which has no fragment, so Back from Plans changed the URL but stayed on Plans, and it wrote #order and #history instead of the visible names. The SEO filing's object lookup crashed the page on /#hasOwnProperty, /#valueOf, /#propertyIsEnumerable and /#toLocaleString (full-page 'Application error' that persisted on reload until the fragment was removed; saved loans untouched), and after 'Clear every loan' then Back a stale #plans entry sent the next first loan to Plans with the form gone.

Fix choice: the SEO filing's fragment patch, because it uses the visible names, gives Loans no fragment so the first, hashless history entry maps to Loans, keeps any query string, and honours a section link only when loans are saved. Two skeptic corrections are added: the Map lookup and the no-loans guard effect. Each was built on top of the SEO patch separately; they touch different lines but were not built together, so run the test list once on the combined change. On the SEO patch, measured under Next 14.2.35: the same document throughout (a window marker survived and main was not remounted), scroll restored on Back and Forward, 0 extra document requests, 0 console errors. Known leftovers the skeptics accepted: the skip link pushes a #main entry, so the next Back is one press with no visible change, and a reload at #main opens Loans, as every reload does today. Interactions: if RES-11's draft fix lands, close the form in onPop only when no draft exists, `if (!readDraft()) { setAdding(false); setEditing(null); }`; without that guard a half-filled form plus Back then Forward left a draft with no form on screen and Edit blocked. TABS.find((t) => t.id === tab)!.long + " | Loan Desk by Cense" : DEFAULT_TITLE; }, [tab, hydrated, loans.length]);`. Both agentic skeptics built a version of it (root name 'Payoff | Loan Desk by Cense'); it is not a WCAG requirement. Not tested with iOS Safari's swipe-back.
