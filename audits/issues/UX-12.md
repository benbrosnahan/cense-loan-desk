# UX-12: Servicer instruction for extra payments is buried

**P2** · effort S · UX and UI

The instruction that makes extra payments count sits at the bottom of Payoff, below every loan in the order, and says only 'your servicer', so a borrower adding extra money can miss it and the servicer may spread the money across loans or push the due date ahead instead.

## Measured

Audit fixture at 375x812 with $0 extra: the notice title 'One thing that undoes all of this' is at docTop 3098 of 3925px, 1,665px below 'Where should extra money go?' (docTop 1433), after all 8 order rows. At the $100 the impact describes it is 3362 of 4189 (1,898px below that heading, 2,666px below the amount input), and at 1440x900 with $100, 2678 of 3284 (1,282px below). Only the 'Save a dated record' card, 20px below, and the footer follow it. The notice says 'your servicer' while the summary says '2 servicers' and no order row names a servicer; it does name the first-ranked loan ('2024–25 unsubsidized'). It has 0 controls and is not a heading, and the tab has no copy button, though the text is selectable (user-select auto; a range selection returned all 315 characters).

## Required

The instruction sits above the payoff order, next to the loan it is about; it names that loan's servicer when one is known and falls back to 'your servicer' for 'Not sure yet' or 'Other'; a button copies a request the servicer can act on, identifying the loan by date and rate rather than only by the app's nickname, and says 'Copied' only when the copy worked. The order itself stays on Payoff, as designed.

## Reproduce

1. Open http://localhost:3100 and click 'Look around with example loans' (8 loans, 4 with Nelnet and 4 with MOHELA).
2. Open Plans and press 'Use <plan> as my plan' on the top pick.
3. Open Payoff and tap $100 under 'Extra each month'.
4. Scroll down. The 'Where should extra money go?' card lists all 8 loans, and only after the last one does the warning 'One thing that undoes all of this' appear. It says to write to 'your servicer' although the loans sit with two, and offers nothing to copy.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "UX-12"`.

## Fix

src/components/ranking/RankingPanel.tsx. Move the Notice from lines 497-504 into the 'Where should extra money go?' card, just above `<Eyebrow className="mt-6">Your order</Eyebrow>` (line 440), name the servicer only when it is a real one, and add a copy button. After the `if (!loans.length) return null;` guard (line 146):
```tsx
const target = ranked[0]?.loan;
const named =
  target && target.servicer !== SERVICER_UNKNOWN && target.servicer !== "Other"
    ? target.servicer
    : "your servicer";
// The servicer does not know the app's nicknames, so the request carries date and rate.
const request = target
  ? `Please apply any amount above my scheduled payment to the principal of my loan disbursed ${niceDate(target.disbursementDate)} at ${pct(target.rate)} ("${target.nickname}"), and do not advance my due date.`
  : "";
const copyRequest = () => {
  const fail = () => onCopied("Could not copy. Press and hold the text to select it.");
  if (!navigator.clipboard) return fail();
  navigator.clipboard.writeText(request).then(() => onCopied("Copied"), fail);
};
```
The moved notice:
```tsx
<Notice tone="warn" className="mt-6" title={`Tell ${named} where extra money goes`}>
  Sending extra money without instructions usually gets it spread across
  every loan, or treated as paying next month&apos;s bill early. Tell {named} in
  writing to apply anything above the scheduled amount to the principal of{" "}
  <strong>{target?.nickname ?? "the loan you chose"}</strong>, and not to
  advance your due date.
  {target && (
    <div className="no-print mt-3">
      <Button size="sm" variant="secondary" onClick={copyRequest}>Copy the request</Button>
    </div>
  )}
</Notice>
```
Import SERVICER_UNKNOWN from @/types and niceDate from @/lib/utils, add `onCopied: (message: string) => void` to Props (lines 47-53), and in src/app/page.tsx:807-817 pass `onCopied={(m) => say(m)}`, since the panel has no toast of its own. The clipboard write stays on the device.

## Severity

Reaches every borrower who sets an extra payment; those who stop reading after the amount, or switch sections from the sticky bar, never see it (anyone following the page's own Next card does scroll past it). The text is present and correct and no figure is wrong, so it is a bounded defect and a meaningful missed opportunity rather than a wrong number.

## Verification

Confirmed by 2 of 2 skeptics (reproduce, standards); both kept P2 and both corrected the fix, which would have printed 'Tell Not sure yet where extra money goes' for the form's default servicer.

<details><summary>Dissent and notes</summary>

No skeptic disputed the placement or P2. Corrections adopted: the filed numbers are the $0 state, and at the $100 the impact describes the notice sits 264px further down, so the finding understates it; 'cannot be copied' is literally false, because the text is selectable, and what is missing is a copy button and a request worded for the servicer, which the merged AI rated only P3; 'vague' applies only with two or more servicers, since the notice already names the loan; 'may never reach' applies to a borrower who leaves early or switches sections from the sticky bar, because anyone following the page's own Next card scrolls past it. Fix: the filed title `Tell ${ranked[0].loan.servicer} where extra money goes` reads 'Tell Not sure yet where extra money goes' for the form's default servicer (LoanForm.tsx:107, whose hint says it is fine to leave for later) and 'Tell Other where extra money goes' for Other; the filed button toasted 'Copied' even when the write was rejected and threw an uncaught TypeError where the clipboard API is missing; and the body still said 'your servicer'. The two skeptics differed on the request and on failure: the reproduce skeptic's request names the loan only by nickname and reports a failed copy, while the standards skeptic's carries the disbursement date and rate and stays silent when the copy fails.

Fix choice: the standards skeptic's request text, because a servicer cannot match the app's nickname to a loan while date and rate identify it, with the reproduce skeptic's failure handling, so a borrower is told when nothing was copied and a missing clipboard API cannot throw. The combination itself was not built. The moved notice is still 608px below the 'Where should extra money go?' heading, because the strategy choice and its cost note come first.
