# UX-18: Payoff order rows repeat stock sentences

**P3** · effort S · UX and UI

The Payoff order list repeats a stock sentence under seven of eight loans and shows one rate as both 5.50% and 5.5%, so phone users scroll a long list for one useful line, and the 'Smallest balance first' rows describe a payment rollover the app does not model.

## Measured

At 375x812 with the eight-loan fixture and Standard chosen, 'Highest rate first' ends 4 rows with 'Also {rate}%, but a larger balance than the one above, so it waits its turn.' and 3 rows with '{rate}%. Next in line once the loans above it are gone.'; only row 1 says something specific to its loan. 'Smallest balance first' ends 6 rows with 'Next smallest. Each account you close frees up its minimum for the next one.' The two 5.5% rows show '5.50%' in their figures (pct() at RankingPanel.tsx:471) and '5.5%' in their sentence (`${loan.rate}%` at ranking.ts:40 and :42). projectPayoff gives identical output with minPayment 0 and 900, so there is no per-loan minimum to free: in a replica whose totals match projectPayoff ($500, $3,000 and $9,000 at 6%, $200 required, $100 extra), the month before the first loan clears pays 103.17, 49.21 and 147.62, and the month after pays 149.78 and 150.22, so the cleared loan's share spreads across both remaining loans and only the extra moves to the next one, as ranking.ts:110-125 describes. The list is 1,221px tall (1,279px under 'Smallest balance first', 1,029px with no plan chosen). From the top of the list to the 'One thing that undoes all of this' notice is 1,280px; from the heading 'Where should extra money go?' to that notice is 1,665px at $0 extra (385px of it above the list) and 1,898px at $100 extra. 'Gone by {month}' already shows on each row when a plan pays off.

## Required

The ordering rule stated once; each row carries only what differs (its name, rate, balance and 'Gone by' date); one rate format; explanatory copy that matches what the projection does.

## Reproduce

1. Open http://localhost:3100 at 375x812 and click 'Look around with example loans' (eight loans).
2. Open Repayment plans and tap 'Use … as my plan' on any plan (the skeptic used Standard).
3. Open Payoff and scroll to 'Your order' under 'Where should extra money go?'. With 'Highest rate first', 4 rows end 'Also …, but a larger balance than the one above, so it waits its turn.' and 3 end '… Next in line once the loans above it are gone.'; the two Sophomore rows show '5.50%' in their figures and '5.5%' in their sentence.
4. Tap 'Smallest balance first': 6 rows read 'Next smallest. Each account you close frees up its minimum for the next one.'

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "UX-18"`.

## Fix

Say the rule once, keep the reason on the first row only, and use one rate format. Two files.

src/lib/ranking.ts, replacing rankLoans (:26-57):
```ts
// Same format as pct() in utils.ts. Kept local, as calc.ts keeps money():
// verify.mjs compiles calc, ranking, plans and types alone (verify.mjs:50).
const pct = (n: number) => `${n.toFixed(2).replace(/\.00$/, "")}%`;

export function rankLoans(loans: Loan[], strategy: Strategy): RankedLoan[] {
  const ordered = orderLoans(loans, strategy);
  return ordered.map((loan, i) => {
    // Only the first loan says why. The rule for the rest is stated once above the list.
    let reason = "";
    if (i === 0 && strategy === "avalanche") {
      const tied = ordered.filter((l) => l.rate === loan.rate).length > 1;
      reason = tied
        ? `Highest rate you carry at ${pct(loan.rate)}, and the smaller of the loans at that rate, so it clears first.`
        : `Highest rate you carry at ${pct(loan.rate)}. Every extra dollar does the most work here.`;
    } else if (i === 0) {
      reason = "Smallest balance you have, so this is the fastest account to clear off the list entirely.";
    }
    return { loan, rank: i + 1, reason };
  });
}
```

src/components/ranking/RankingPanel.tsx: add a rule to STRATEGY_COPY (:55-68, adding rule: string to its type):
```ts
avalanche: { …, rule: "Highest rate first. At equal rates, the smaller balance goes first. Once a loan is gone, the extra moves to the next one down." },
snowball: { …, rule: "Smallest balance first. At equal balances, the higher rate goes first. Once a loan is gone, the extra moves to the next one down." },
```
show it under the 'Your order' eyebrow (:440):
```tsx
<p className="mt-1 text-sm leading-relaxed text-slate-700">{STRATEGY_COPY[strategy].rule}</p>
```
and render the reason paragraph (:476-483) only when there is one:
```tsx
{reason && (
  <p className="mt-1 text-sm leading-snug text-slate-700">
    {rank === 1 && <Badge tone="accent" className="mr-1.5">Extra goes here</Badge>}
    {reason}
  </p>
)}
```
'Gone by {month}' already shows on every row when a plan pays off (:484-488), so each row keeps its date. No dependency; nothing leaves the device.

## Severity

Every borrower with several loans who opens Payoff reads this list (7 of 8 rows on the example loans carry a stock sentence), but every date and dollar figure in it is right; the one inaccurate sentence describes a mechanism, changes no figure, and appears only after switching to the non-default 'Smallest balance first', so this is reading load rather than a misleading figure.
