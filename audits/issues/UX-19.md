# UX-19: Adding several loans costs avoidable taps

**P3** · effort S · UX and UI

Adding several loans costs an extra tap per school year because the next form stays on Unsubsidized, and after Cancel a new loan opens pre-filled with a year, rate and type the borrower never picked.

| | |
|---|---|
| Who it hurts | A borrower entering eight loans on a phone pays 3 avoidable taps, and one who cancels and later adds another loan starts from a year, rate and type they never chose for it; if they type only the balance, those values are what gets saved. |
| Standard | No pass/fail standard. Nielsen heuristic 7, flexibility and efficiency of use. |
| Where | First run and Loans tab: the 'Add a loan' form during a 'Save and add another' chain, and the next new-loan form opened after Cancel. Measured at 375x812 on localhost:3100; the defaults logic does not depend on screen width. |
| Code | [`src/app/page.tsx:234`](../../src/app/page.tsx#L234), [`src/app/page.tsx:236`](../../src/app/page.tsx#L236), [`src/app/page.tsx:288`](../../src/app/page.tsx#L288), [`src/app/page.tsx:574`](../../src/app/page.tsx#L574), [`src/components/loans/LoanForm.tsx:102`](../../src/components/loans/LoanForm.tsx#L102) |
| Test | `ux-copy.spec.mjs`: "UX-19 the subsidized and unsubsidized loans of each year need no type tap, and a new add after Cancel starts blank" |

## Measured

Entering the 8-loan fixture (a subsidized and an unsubsidized loan for each of four school years) with real touch taps takes 5, 2, 4, 2, 6, 2, 4 and 2 taps per loan, 28 including the opening tap. After an unsubsidized loan the next form keeps Unsubsidized and blanks the date, so loans 3, 5 and 7, each the next year's subsidized loan, need a type tap on top of the year tap. When the first form settles (scrollY 250), Save loan sits at y=1278 in the 812px viewport, and 'Save and add another' starts 1315 to 1334px down on open (943px after the balance is typed, on most loans); it was never inside the viewport on any of the 8 loans, so every loan also needs a scroll. After 'Save and add another' on a 2024–25 subsidized loan, then Cancel, then 'Add a loan', the new form opens with date 2024-09-01, rate 6.53 and Unsubsidized, and its hints say the date and rate were filled in.

## Required

Carried-over defaults follow the pattern the code comment at page.tsx:232-233 already names (a subsidized and an unsubsidized loan each year), so next year's subsidized loan needs no type tap; and a new add started after Cancel opens with a blank year and rate and the default type, keeping only the servicer.

## Reproduce

On http://localhost:3100 at 375x812 with no saved data:
1. Tap 'Add my first loan'. Tap '2022–23', type 3500 in 'What you owe on it today', choose Nelnet under 'Who do you pay?', and tap 'Save and add another'.
2. The next form is already on 2022–23, Unsubsidized, 4.99% and Nelnet. Type 2396 and tap 'Save and add another'.
3. The third form has no year and still says Unsubsidized. To enter the 2023–24 subsidized loan you must tap '2023–24' and also tap 'Subsidized': 4 taps for this loan instead of 3. Loans 5 and 7 repeat this. Every form also needs a scroll to reach its Save buttons.
4. Stale defaults: save a 2024–25 subsidized loan with 'Save and add another', tap Cancel on the form that opens, then tap 'Add a loan'. The new form opens on 2024–25 (date 2024-09-01), rate 6.53 and Unsubsidized.

Or run its test from `audits/`: `AUDIT_SHOW_KNOWN=1 npx playwright test -g "UX-19"`.

## Fix

Two edits in src/app/page.tsx.

1. Line 236, in saveLoan's 'Save and add another' branch, alternate the pair in both directions:

  kind:
    loan.kind === "direct_sub"
      ? "direct_unsub"
      : loan.kind === "direct_unsub"
        ? "direct_sub"
        : loan.kind,

Lines 237-238 already keep the date after a subsidized loan and blank it after an unsubsidized one, so each pair stays in one school year and the next pair starts with a blank year.

2. Line 288, start every new add from clean defaults, keeping only the servicer:

  const startAdding = () => {
    setFormDefaults({ servicer: formDefaults.servicer });
    setEditing(null);
    setFormKey((k) => k + 1);
    setAdding(true);
  };

Measured on a scratch build with exactly these two edits: 5, 2, 3, 2, 5, 2, 3 and 2 taps per loan, 25 including the opening tap, so 3 fewer. After Cancel and 'Add a loan', the date and rate are blank, the type is Subsidized and the servicer is kept. A subsidized loan saved with 'Save and add another' still carries its date to the unsubsidized one.

## Severity

Any borrower who enters loans with 'Save and add another' pays one avoidable type tap per new school year (3 taps for a typical 8-loan history), and one who cancels mid-chain and later adds a loan starts from stale values. The form labels that year and rate as filled in, and no figure is wrong unless the borrower misses them, so this is efficiency polish.

## Verification

Confirmed by 1 of 1 skeptic (P3 review lens), who reproduced it with real touch taps on localhost:3100 and re-measured the fix on a scratch build.

None on the defect, the severity or the fix. The skeptic corrected the test idea: 'at most 24 taps' only passes if the opening 'Add my first loan' tap is excluded, since the fixed build takes 25 including it.

Trade-off the skeptic named: a borrower whose loans are all unsubsidized now pays one type tap per additional loan, where today the type carries over. The fix still suits this app's main audience, undergraduates with subsidized and unsubsidized pairs, which is the pattern the existing code comment names. The loan type does not feed the money math (calc.ts:57 only tests for parent_plus; export.ts:47-48 use it as labels), so a wrong type default only mislabels the row, its auto-name and the export. Putting the reset in startAdding rather than in onCancel (page.tsx:391 and 574) also covers leaving the chain by switching tabs, because goTo closes the form without clearing formDefaults. The Save buttons sitting below the fold on a 375x812 phone is measured but not fixed here: no member proposed a change, and the form scrolls itself to its own top on open (LoanForm.tsx:129-142). Single-member issue. No new dependency, and nothing leaves the device.
